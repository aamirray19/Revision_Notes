# OOP in Python — Topic 3: `this`, Constructor Chaining, Shallow Copy, and Deep Copy

These four concepts are closely connected to object references, initialization, inheritance, and memory management.

We'll cover them in this order:

1. `this` keyword vs. `self` in Python
2. Constructor chaining — within the same class and across inheritance
3. Shallow copy — what gets copied and what remains shared
4. Deep copy — how independent copies of nested objects are created

We'll also look at memory relationships, tricky cases, and interview questions.

## 1. `this` Keyword in Python

### What is `this`?

In languages such as Java, C++, and JavaScript, `this` is used to refer to an object in particular contexts.

Python does **not** have a `this` keyword with the same purpose.

Instead, Python uses the convention **`self`** to refer to the current instance inside instance methods.

### Example

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def display(self):
        print(self.name, self.age)


s1 = Student("Aamir", 22)
s2 = Student("Rahul", 23)
s1.display()
s2.display()
```

**Output:**

```text
Aamir 22
Rahul 23
```

Here:

- When `s1.display()` executes, `self` refers to `s1`.
- When `s2.display()` executes, `self` refers to `s2`.

### How does Python know which object is `self`?

Consider this method:

```python
def display(self):
    print(self.name)
```

When you write:

```python
s1.display()
```

Python effectively executes:

```python
Student.display(s1)
```

It automatically supplies the instance as the first argument.

You can verify this:

```python
class Demo:
    def show(self):
        print(id(self))


d = Demo()
d.show()
print(id(d))
```

**Example output:**

```text
140235115430112
140235115430112
```

Both values are identical because `self` and `d` refer to the same object. The specific number will vary between runs.

### Why do we write `self.name = name`?

This is a frequently misunderstood concept.

```python
class Student:
    def __init__(self, name):
        self.name = name
```

The two occurrences of `name` play different roles:

| Expression | Meaning |
| --- | --- |
| `self.name` | Instance attribute associated with the object. Can be accessed later using `s1.name`. |
| `name` | Local parameter passed to the initializer. Exists as a local name during the method call. |

### What happens if we don't use `self`?

```python
class Student:
    def __init__(self, name):
        name = name


s1 = Student("Aamir")
print(s1.name)
```

**Output:**

```text
AttributeError: 'Student' object has no attribute 'name'
```

**Why?** Because `name = name` only assigns the local variable to itself. It does not create an instance attribute.

### Is `self` mandatory?

The first parameter of a normal instance method receives the instance, but the name `self` is just a convention.

Technically, this works:

```python
class Student:
    def __init__(this, name):
        this.name = name

    def display(this):
        print(this.name)


s1 = Student("Aamir")
s1.display()
```

**Output:**

```text
Aamir
```

However, you should use **`self`** to follow Python conventions.

### `self` vs. `cls`

Another important interview distinction:

| `self` | `cls` |
| --- | --- |
| Refers to an instance | Refers to a class |
| Used conventionally in instance methods | Used conventionally in class methods |
| Accesses instance attributes | Can access class attributes and construct instances |
| Passed automatically for bound instance methods | Passed automatically for class methods |

**Example:**

```python
class Student:
    school = "ABC School"

    def __init__(self, name):
        self.name = name

    def show_name(self):
        print(self.name)

    @classmethod
    def show_school(cls):
        print(cls.school)


s1 = Student("Aamir")
s1.show_name()
Student.show_school()
```

**Output:**

```text
Aamir
ABC School
```

> **Interview takeaway:** Python doesn't use `this` to refer to the current object. It conventionally uses `self`, which is automatically bound to the instance when you call a normal instance method through that instance.

## 2. Constructor Chaining in Python

### What is constructor chaining?

Constructor chaining is the process of having one initialization path invoke another so that initialization logic can be reused.

The concept often appears in two situations:

- Within the same class
- Between parent and child classes

In Java, for example, `this()` and `super()` are used for different kinds of constructor chaining. In Python, constructor chaining works differently.

### A. Constructor chaining within the same class

First, understand that Python doesn't support multiple `__init__()` overloads based on their signatures.

This does not work as you might expect:

```python
class Student:
    def __init__(self):
        print("Default constructor")

    def __init__(self, name):
        print("Parameterized constructor")


s1 = Student("Aamir")
```

**Output:**

```text
Parameterized constructor
```

The second `__init__()` **replaces** the first.

#### Approach 1: Default arguments

```python
class Student:
    def __init__(self, name="Unknown", age=0):
        self.name = name
        self.age = age

    def display(self):
        print(self.name, self.age)


s1 = Student()
s2 = Student("Aamir")
s3 = Student("Rahul", 25)
s1.display()
s2.display()
s3.display()
```

**Output:**

```text
Unknown 0
Aamir 0
Rahul 25
```

A single initializer supports multiple invocation patterns.

#### Approach 2: Alternative constructors using `@classmethod`

Suppose you want to create students either by providing their age or by providing their birth year.

```python
class Student:
    def __init__(self, name, age):
        print("Inside __init__")
        self.name = name
        self.age = age

    @classmethod
    def from_birth_year(cls, name, birth_year):
        print("Inside alternative constructor")
        age = 2026 - birth_year
        return cls(name, age)


s1 = Student("Aamir", 22)
s2 = Student.from_birth_year("Rahul", 2002)
print(s2.name, s2.age)
```

**Output:**

```text
Inside __init__
Inside alternative constructor
Inside __init__
Rahul 24
```

The sequence for `s2` is:

1. `Student.from_birth_year("Rahul", 2002)`
2. `age = 2026 - 2002`
3. `cls("Rahul", 24)`
4. `Student.__init__()` initializes the new instance.

The alternative constructor delegates to the normal class creation process.

**Note:** The age calculation here is simplified; exact age depends on whether the person's birthday has occurred.

### B. Constructor chaining in inheritance

This is the most common meaning of constructor chaining in Python interviews.

Imagine a `Person` class and a `Student` class. A student is also a person, so the student should have the common person attributes.

**Without chaining:**

```python
class Person:
    def __init__(self, name):
        self.name = name


class Student(Person):
    def __init__(self, name, roll_no):
        self.roll_no = roll_no


s1 = Student("Aamir", 101)
print(s1.roll_no)
print(s1.name)
```

**Output:**

```text
101
AttributeError: 'Student' object has no attribute 'name'
```

**Why?** Because `Student` defines its own `__init__()`, and it never calls the parent initializer.

**Solution: `super().__init__()`**

```python
class Person:
    def __init__(self, name):
        print("Person constructor")
        self.name = name


class Student(Person):
    def __init__(self, name, roll_no):
        super().__init__(name)
        print("Student constructor")
        self.roll_no = roll_no


s1 = Student("Aamir", 101)
print(s1.name)
print(s1.roll_no)
```

**Output:**

```text
Person constructor
Student constructor
Aamir
101
```

**What happens internally?**

1. Python creates a `Student` instance.
2. `Student.__init__()` begins execution.
3. `super().__init__(name)` delegates to the next initializer in the method resolution order.
4. `Person.__init__()` sets `self.name`.
5. Execution returns to `Student.__init__()`.
6. `self.roll_no` is initialized.

Notice something important: `self` refers to the **same `Student` object** in both initializers. The parent initializer doesn't create a separate `Person` object.

### C. Multilevel constructor chaining

Consider three classes:

```python
class Grandparent:
    def __init__(self):
        print("Grandparent initialized")


class Parent(Grandparent):
    def __init__(self):
        super().__init__()
        print("Parent initialized")


class Child(Parent):
    def __init__(self):
        super().__init__()
        print("Child initialized")


c = Child()
```

**Output:**

```text
Grandparent initialized
Parent initialized
Child initialized
```

The calls go inward:

1. `Child.__init__()` begins.
2. `Parent.__init__()` begins.
3. `Grandparent.__init__()` runs.
4. `Parent` prints its message.
5. `Child` prints its message.

Because each `print()` occurs **after** its `super().__init__()` call, the output is from grandparent to child. If the prints were before the `super()` calls, the order of those prints would reverse.

### D. Can we call the parent initializer directly?

Yes.

```python
class Parent:
    def __init__(self):
        print("Parent initialized")


class Child(Parent):
    def __init__(self):
        Parent.__init__(self)
        print("Child initialized")
```

This works, but `super().__init__()` is generally preferred.

The reason is important: `super()` follows the **method resolution order (MRO)**, not simply the direct parent class. This makes cooperative initialization work more reliably in multiple inheritance.

**Example:**

```python
class A:
    def __init__(self):
        print("A")
        super().__init__()


class B(A):
    def __init__(self):
        print("B")
        super().__init__()


class C(A):
    def __init__(self):
        print("C")
        super().__init__()


class D(B, C):
    def __init__(self):
        print("D")
        super().__init__()


d = D()
print([cls.__name__ for cls in D.__mro__])
```

**Output:**

```text
D
B
C
A
['D', 'B', 'C', 'A', 'object']
```

The calls follow **D → B → C → A → object**.

This is why calling `super()` does not always mean calling your immediate parent.

> **Interview takeaway:** Constructor chaining promotes code reuse and proper initialization across inherited classes. In Python, `super().__init__()` is the standard mechanism for cooperative initialization.

## 3. Shallow Copy in Python

Before understanding shallow copy, we need to understand how Python handles object references.

### A. Assignment does not create a copy

```python
list1 = [10, 20, 30]
list2 = list1
list2.append(40)
print(list1)
print(list2)
```

**Output:**

```text
[10, 20, 30, 40]
[10, 20, 30, 40]
```

**Why did modifying `list2` also modify `list1`?** Because both variables reference the **same list object**. Assignment copies the reference, not the list itself.

Let's confirm:

```python
print(list1 is list2)  # True
```

The `is` operator checks whether two variables reference the same object.

### B. What is a shallow copy?

A **shallow copy** creates a new outer object but keeps references to the original nested objects.

Python provides the `copy` module:

```python
import copy

original = [[10, 20], [30, 40]]
shallow = copy.copy(original)
```

Now `original` and `shallow` are different outer lists, but their inner lists are shared.

```text
original ──► outer list A ──► inner list [10, 20]
                        └───► inner list [30, 40]
shallow  ──► outer list B ──► same inner list [10, 20]
                        └───► same inner list [30, 40]
```

### C. What happens when we modify a nested object?

```python
import copy

original = [[10, 20], [30, 40]]
shallow = copy.copy(original)
shallow[0][0] = 999
print(original)
print(shallow)
```

**Output:**

```text
[[999, 20], [30, 40]]
[[999, 20], [30, 40]]
```

Both changed because `shallow[0] is original[0]` evaluates to `True`. Both outer lists refer to the same first inner list.

### D. What happens when we modify only the outer list?

```python
import copy

original = [[10, 20], [30, 40]]
shallow = copy.copy(original)
shallow.append([50, 60])
print(original)
print(shallow)
```

**Output:**

```text
[[10, 20], [30, 40]]
[[10, 20], [30, 40], [50, 60]]
```

Only `shallow` changed, because `append()` changes its outer list, and the outer lists are independent objects.

> **Fundamental rule:** Shallow copy separates the outer container, not the existing nested mutable objects.

### E. Shallow copy with class objects

The same concept works with instances of user-defined classes.

```python
import copy

class Student:
    def __init__(self, name, subjects):
        self.name = name
        self.subjects = subjects


s1 = Student("Aamir", ["Math", "Python"])
s2 = copy.copy(s1)
s2.name = "Rahul"
s2.subjects.append("Java")
print(s1.name)
print(s2.name)
print(s1.subjects)
print(s2.subjects)
```

**Output:**

```text
Aamir
Rahul
['Math', 'Python', 'Java']
['Math', 'Python', 'Java']
```

**Why did changing `s2.name` not change `s1.name`?** Assigning to `s2.name` changes the attribute of `s2`, which is a different outer object.

**Why did changing `s2.subjects` affect `s1.subjects`?** Both instances refer to the same mutable list.

We can verify:

```python
print(s1 is s2)                    # False
print(s1.subjects is s2.subjects)  # True
```

For ordinary user-defined objects, `copy.copy()` generally copies the instance without calling its `__init__()` again. Custom copy behavior can change this.

## 4. Deep Copy in Python

### What is a deep copy?

A **deep copy** creates a new compound object and recursively copies the objects it contains, subject to Python's copying rules.

Unlike shallow copy, nested mutable objects are ordinarily copied too.

Python provides `copy.deepcopy()`.

### A. Basic example

```python
import copy

original = [[10, 20], [30, 40]]
deep = copy.deepcopy(original)
deep[0][0] = 999
print(original)
print(deep)
```

**Output:**

```text
[[10, 20], [30, 40]]
[[999, 20], [30, 40]]
```

The original remains unchanged because `deep[0]` and `original[0]` are distinct inner lists.

### B. Deep copy with a custom class

```python
import copy

class Student:
    def __init__(self, name, subjects):
        self.name = name
        self.subjects = subjects


s1 = Student("Aamir", ["Math", "Python"])
s2 = copy.deepcopy(s1)
s2.name = "Rahul"
s2.subjects.append("Java")
print(s1.name)
print(s2.name)
print(s1.subjects)
print(s2.subjects)
```

**Output:**

```text
Aamir
Rahul
['Math', 'Python']
['Math', 'Python', 'Java']
```

Now both the outer `Student` instance and its nested `subjects` list are independent.

```python
print(s1 is s2)                    # False
print(s1.subjects is s2.subjects)  # False
```

### C. Does deep copy copy absolutely everything?

Not necessarily. Deep copying doesn't mean every value in memory must get a new identity.

```python
import copy

original = [10, "Python", (1, 2)]
deep = copy.deepcopy(original)
print(original is deep)
print(original[0] is deep[0])
```

**Output:**

```text
False
True
```

**Why is the integer shared?** Because integers are immutable. Sharing an immutable integer doesn't create the same mutation risks as sharing a list.

Other objects, such as functions and classes, can also be returned unchanged by the copying mechanism. Some types, including open files and sockets, cannot generally be deep-copied.

> **Accurate rule:** Deep copy recursively reproduces copyable compound state, while allowing some objects to remain shared according to their types and copy protocols.

## 5. Shallow Copy vs. Deep Copy — Comparison

| Feature | Shallow copy | Deep copy |
| --- | --- | --- |
| Function | `copy.copy()` | `copy.deepcopy()` |
| New outer object | Generally yes | Generally yes |
| Nested mutable objects | Shared | Recursively copied |
| Memory usage | Usually lower | Usually higher |
| Execution cost | Usually lower | Usually higher |
| Nested mutations | Can affect original | Usually isolated |
| Best used when | Nested objects are immutable or sharing is intended | Independent nested mutable state is required |

### Worked example: Compare all three behaviors

The original lesson included an interactive selector. Here is a copyable, static Markdown version of the same experiment.

**Copy methods:** assignment, shallow copy, deep copy.

**Modification choices:** change a nested list (`copied[0][0] = 99`) or append to the outer list (`copied.append([50, 60])`).

```python
import copy

original = [[10, 20], [30, 40]]
copied = copy.copy(original)  # Try: original, copy.copy(original), copy.deepcopy(original)

copied[0][0] = 99             # Or try: copied.append([50, 60])

print(original)
print(copied)
```

**Output for the shallow-copy/nested-mutation version shown:**

```text
[[99, 20], [30, 40]]
[[99, 20], [30, 40]]
```

**Expected behavior:**

| Copy method | Change nested list | Append to outer list |
| --- | --- | --- |
| Assignment (`copied = original`) | Both change | Both change |
| Shallow (`copy.copy(original)`) | Both change | Only copied outer list changes |
| Deep (`copy.deepcopy(original)`) | Only copied nested list changes | Only copied outer list changes |

## 6. Tricky Interview Cases

### Case 1: Shallow copy and reassignment

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.copy(a)
b[0] = [99, 100]
print(a)
print(b)
```

**Output:**

```text
[[1, 2], [3, 4]]
[[99, 100], [3, 4]]
```

**Why didn't the original change?** Because `b[0] = [99, 100]` replaces a reference in the outer list `b`. It does not mutate the inner list that `a[0]` references.

Compare that with:

```python
b[0][0] = 99
```

That mutates the shared inner list (when `b[0]` still refers to it).

This is the distinction between **reassignment** and **mutation**.

### Case 2: Shallow copying a flat list

```python
a = [10, 20, 30]
b = a.copy()
b[0] = 99
print(a)
print(b)
```

**Output:**

```text
[10, 20, 30]
[99, 20, 30]
```

Even though this is a shallow copy, the original doesn't change. The two outer lists are separate. The elements are immutable integers, and assigning a new value to `b[0]` only changes a reference in `b`.

For a flat list of immutable elements, shallow copy is usually sufficient.

### Case 3: Deep copy preserves internal shared references

This is more advanced.

```python
import copy

shared = [10, 20]
original = [shared, shared]
deep = copy.deepcopy(original)
print(original[0] is original[1])
print(deep[0] is deep[1])
print(original[0] is deep[0])
```

**Output:**

```text
True
True
False
```

**Why does `deep[0] is deep[1]` return `True`?** Because `deepcopy()` keeps track of objects it has already copied using an internal memoization mechanism.

It doesn't blindly create another copy every time it encounters a reference to the same object. This is also what helps `deepcopy()` correctly handle many cyclic object graphs.

### Case 4: Does `list.copy()` perform deep copying?

No.

```python
a = [[1, 2], [3, 4]]
b = a.copy()
c = a[:]
print(a[0] is b[0])  # True
print(a[0] is c[0])  # True
```

Both `.copy()` and slicing create **shallow copies** of lists. Similarly, `dict.copy()` creates a shallow copy of a dictionary.

## 7. Frequently Asked Interview Questions

### Q1. What is the difference between `this` in Java and `self` in Python?

Java has a `this` keyword that refers to the current object. Python conventionally uses `self`, an ordinary parameter receiving the current instance. `self` is not a reserved keyword.

### Q2. Can we use `this()` for constructor chaining in Python?

No. Python doesn't provide Java-style `this()` constructor chaining. Instead, use default arguments, helper methods, or `@classmethod` alternative constructors.

### Q3. What is the difference between `super().__init__()` and `Parent.__init__(self)`?

`super().__init__()` follows the class's MRO, while `Parent.__init__(self)` explicitly invokes the named parent's initializer. Cooperative multiple inheritance generally favors `super()`.

### Q4. Does shallow copy create a separate object?

For ordinary lists and user-defined instances, yes. But nested mutable objects can remain shared, and some immutable or specially handled objects may be returned unchanged.

### Q5. Is deep copy always better than shallow copy?

No. Deep copying can consume more memory and processing time. It can also duplicate state that should remain shared, or fail on objects that aren't copyable.

### Q6. Does `copy.deepcopy()` create a completely independent copy of every object?

Not always. It recursively copies supported nested objects, but immutable and specially handled objects may remain shared.

### Q7. What happens when `b = a`?

`b` refers to the same object as `a`. No new object is created by that assignment.

## 9. Final Revision Notes

| Topic | What you should remember |
| --- | --- |
| `this` / `self` | Python uses `self` by convention to refer to the receiving instance. |
| Constructor chaining | Reuses initialization logic through delegation or `super()`. |
| `super()` | Follows MRO and supports cooperative initialization. |
| Assignment `b = a` | Creates another reference to the same object. |
| Shallow copy | New outer object, shared references to nested objects. |
| Deep copy | Recursively copies supported nested state. |
| Mutation | Changing a shared mutable object affects every reference to it. |
| Reassignment | Changing one reference doesn't necessarily modify the object previously referenced. |

The three most important distinctions from this lesson are:

1. **`self` is an instance reference, not a Python keyword.**
2. **`super().__init__()` helps initialize an object through its inheritance chain; it doesn't create separate parent objects.**
3. **Shallow and deep copying differ in how they handle nested object references, not simply whether they create a new outer object.**

Once you understand object identity, references, and mutation, most shallow-copy and deep-copy interview questions become straightforward.
