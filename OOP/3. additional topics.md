# Topic 3: `this`, Constructor Chaining, Shallow Copy and Deep Copy

> **TL;DR:** Python has no `this` keyword; it uses **`self`**, an ordinary first parameter bound to the current instance. **Constructor chaining** reuses initialization logic via default arguments, `@classmethod` alternative constructors, or `super().__init__()` (which follows the **MRO**). **Assignment** copies a reference, a **shallow copy** gets a new outer object that shares nested objects, a **deep copy** recursively copies nested mutable state.

---

## 1. `this` vs `self`

Java, C++ and JavaScript use the `this` keyword to refer to the current object. Python has **no** `this` keyword: it uses **`self`**, by convention the first parameter of an instance method. (Basics in [Topic 1: Classes and Objects](1.%20Classes%20and%20Objects.md).)

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def display(self):
        print(self.name, self.age)


s1 = Student("Aamir", 22)
s2 = Student("Rahul", 23)
s1.display()   # Aamir 22
s2.display()   # Rahul 23
```

- In `s1.display()`, `self` is `s1`. In `s2.display()`, `self` is `s2`.

### How Python binds `self`

```python
s1.display()          # what you write
Student.display(s1)   # what Python effectively runs
```

- Python passes the instance as the first argument automatically.

Proof that `self` is the calling object:

```python
class Demo:
    def show(self):
        print(id(self))


d = Demo()
d.show()      # 140235115430112
print(id(d))  # 140235115430112  (same object; the number varies per run)
```

### Why `self.name = name`?

```python
class Student:
    def __init__(self, name):
        self.name = name
```

| Expression | Meaning |
|---|---|
| `self.name` | **Instance attribute** stored on the object; accessible later as `s1.name` |
| `name` | **Local parameter** of `__init__`; exists only during the call |

Without `self`:

```python
class Student:
    def __init__(self, name):
        name = name        # assigns the local to itself; nothing stored on the object


s1 = Student("Aamir")
print(s1.name)
```

```text
AttributeError: 'Student' object has no attribute 'name'
```

### `self` is a convention, not a keyword

The first parameter receives the instance whatever it's named. This works, but always use `self`:

```python
class Student:
    def __init__(this, name):
        this.name = name

    def display(this):
        print(this.name)


s1 = Student("Aamir")
s1.display()   # Aamir
```

### `self` vs `cls`

| `self` | `cls` |
|---|---|
| Refers to an **instance** | Refers to the **class** |
| First parameter of instance methods | First parameter of `@classmethod` methods |
| Accesses instance attributes | Accesses class attributes; can construct instances (`cls(...)`) |
| Passed automatically for bound instance methods | Passed automatically for class methods |

```python
class Student:
    school = "ABC School"

    def __init__(self, name):
        self.name = name

    def show_name(self):
        print(self.name)

    @classmethod
    def show_school(cls):
        print(cls.school)


s1 = Student("Aamir")
s1.show_name()          # Aamir
Student.show_school()   # ABC School
```

> **Key point:** Python doesn't use `this`. It uses `self`, which is automatically bound to the instance when you call an instance method through that instance.

## 2. Constructor Chaining

**Constructor chaining** = one initialization path calls another so initialization logic is reused. It shows up in two places:

- **Within the same class** (Java uses `this(...)`)
- **Between parent and child classes** (Java uses `super(...)`)

Python has no `this()` call and works differently. Constructor basics: [Topic 2: Constructors](2.%20constructors.md).

### Same class: no `__init__` overloading

Python does not overload `__init__` by signature. A second definition **replaces** the first.

```python
class Student:
    def __init__(self):
        print("Default constructor")

    def __init__(self, name):
        print("Parameterized constructor")


s1 = Student("Aamir")   # Parameterized constructor
```

- `Student()` would now raise `TypeError` (missing `name`): the no-arg version no longer exists. See overloading in [Topic 4: Polymorphism](4.%20Polymorphism.md).
- Two Pythonic replacements: **default arguments** and **`@classmethod` alternative constructors**.

### Approach 1: Default arguments

```python
class Student:
    def __init__(self, name="Unknown", age=0):
        self.name = name
        self.age = age

    def display(self):
        print(self.name, self.age)


s1 = Student()
s2 = Student("Aamir")
s3 = Student("Rahul", 25)
s1.display()   # Unknown 0
s2.display()   # Aamir 0
s3.display()   # Rahul 25
```

- One initializer supports several call patterns.

### Approach 2: Alternative constructors with `@classmethod`

Create a student from an age **or** from a birth year:

```python
class Student:
    def __init__(self, name, age):
        print("Inside __init__")
        self.name = name
        self.age = age

    @classmethod
    def from_birth_year(cls, name, birth_year):
        print("Inside alternative constructor")
        age = 2026 - birth_year
        return cls(name, age)


s1 = Student("Aamir", 22)
s2 = Student.from_birth_year("Rahul", 2002)
print(s2.name, s2.age)
```

```text
Inside __init__
Inside alternative constructor
Inside __init__
Rahul 24
```

Sequence for `s2`:

1. `Student.from_birth_year("Rahul", 2002)` runs.
2. `age = 2026 - 2002` → `24`.
3. `cls("Rahul", 24)` is called.
4. `Student.__init__()` initializes the new instance.

- The alternative constructor **delegates** to the normal creation process (`cls(...)`), so `__init__` logic isn't duplicated.
- Using `cls` (not `Student`) means subclasses calling it get a subclass instance.
- The age math is simplified; real age depends on whether the birthday has passed.

### Inheritance: `super().__init__()`

The most common meaning of constructor chaining in interviews. A `Student` is a `Person`, so it needs `Person`'s attributes too.

**Without chaining:**

```python
class Person:
    def __init__(self, name):
        self.name = name


class Student(Person):
    def __init__(self, name, roll_no):
        self.roll_no = roll_no


s1 = Student("Aamir", 101)
print(s1.roll_no)
print(s1.name)
```

```text
101
AttributeError: 'Student' object has no attribute 'name'
```

- `Student` defines its own `__init__()`, which overrides `Person.__init__()` and never calls it, so `self.name` is never set.

**Fix: call `super().__init__()`**

```python
class Person:
    def __init__(self, name):
        print("Person constructor")
        self.name = name


class Student(Person):
    def __init__(self, name, roll_no):
        super().__init__(name)
        print("Student constructor")
        self.roll_no = roll_no


s1 = Student("Aamir", 101)
print(s1.name)
print(s1.roll_no)
```

```text
Person constructor
Student constructor
Aamir
101
```

**Internals: what happens**

1. Python creates a `Student` instance.
2. `Student.__init__()` starts.
3. `super().__init__(name)` delegates to the **next initializer in the MRO** (here `Person`).
4. `Person.__init__()` sets `self.name`.
5. Control returns to `Student.__init__()`.
6. `self.roll_no` is set.

- `self` is the **same `Student` object** in both initializers. The parent initializer does **not** create a separate `Person` object.

### Multilevel chaining

```python
class Grandparent:
    def __init__(self):
        print("Grandparent initialized")


class Parent(Grandparent):
    def __init__(self):
        super().__init__()
        print("Parent initialized")


class Child(Parent):
    def __init__(self):
        super().__init__()
        print("Child initialized")


c = Child()
```

```text
Grandparent initialized
Parent initialized
Child initialized
```

Calls go **inward**, prints come back **outward**:

1. `Child.__init__()` starts.
2. `Parent.__init__()` starts.
3. `Grandparent.__init__()` runs and prints.
4. `Parent` prints.
5. `Child` prints.

- Each `print()` is **after** its `super().__init__()`, so output goes grandparent → child.
- Put the prints **before** the `super()` calls and the order reverses (child → grandparent).

### `Parent.__init__(self)` vs `super().__init__()`

Calling the parent directly works:

```python
class Parent:
    def __init__(self):
        print("Parent initialized")


class Child(Parent):
    def __init__(self):
        Parent.__init__(self)
        print("Child initialized")
```

But `super().__init__()` is preferred: it follows the **method resolution order (MRO)**, not just the direct parent. That makes **cooperative initialization** work in multiple inheritance.

```python
class A:
    def __init__(self):
        print("A")
        super().__init__()


class B(A):
    def __init__(self):
        print("B")
        super().__init__()


class C(A):
    def __init__(self):
        print("C")
        super().__init__()


class D(B, C):
    def __init__(self):
        print("D")
        super().__init__()


d = D()
print([cls.__name__ for cls in D.__mro__])
```

```text
D
B
C
A
['D', 'B', 'C', 'A', 'object']
```

- Calls follow **D → B → C → A → object**.
- Inside `B`, `super()` goes to **`C`** (B's sibling), not `A`. `super()` means "next in the MRO", not "my parent".
- Each class runs exactly once. MRO details: [Topic 5: Inheritance](5.%20inheritance.md).

| `super().__init__(...)` | `Parent.__init__(self, ...)` |
|---|---|
| Calls the **next class in the MRO** | Calls the **named** class, hard-coded |
| `self` passed automatically | `self` passed explicitly |
| Safe for multiple inheritance (each class once) | In diamonds, a class can run twice or be skipped |
| Survives renaming the parent | Must be edited if the parent changes |

> **Key point:** Constructor chaining reuses code and makes sure every class in the hierarchy initializes its part. In Python, `super().__init__()` is the standard mechanism for cooperative initialization.

## 3. Assignment Does Not Copy

```python
list1 = [10, 20, 30]
list2 = list1
list2.append(40)

print(list1)            # [10, 20, 30, 40]
print(list2)            # [10, 20, 30, 40]
print(list1 is list2)   # True
```

- Assignment copies the **reference**, not the object. Both names point to the **same list**, so a change through one is visible through the other.
- `is` checks **identity** (same object). Same idea for class instances: [Topic 1, Section 10](1.%20Classes%20and%20Objects.md).

## 4. Shallow Copy

A **shallow copy** creates a **new outer object**, but fills it with **references to the same nested objects**. Use `copy.copy()`.

```python
import copy

original = [[10, 20], [30, 40]]
shallow = copy.copy(original)
```

```text
original ──► outer list A ──► inner list [10, 20]
                        └───► inner list [30, 40]
shallow  ──► outer list B ──► same inner list [10, 20]
                        └───► same inner list [30, 40]
```

### Mutating a nested object: both change

```python
import copy

original = [[10, 20], [30, 40]]
shallow = copy.copy(original)
shallow[0][0] = 999

print(original)   # [[999, 20], [30, 40]]
print(shallow)    # [[999, 20], [30, 40]]
```

- `shallow[0] is original[0]` → `True`: both outer lists hold the same first inner list.

### Modifying the outer container: only the copy changes

```python
import copy

original = [[10, 20], [30, 40]]
shallow = copy.copy(original)
shallow.append([50, 60])

print(original)   # [[10, 20], [30, 40]]
print(shallow)    # [[10, 20], [30, 40], [50, 60]]
```

- `append()` changes the outer list, and the outer lists are independent objects.

> **Rule:** a shallow copy separates the **outer container**, not the nested mutable objects inside it.

### Shallow copy of class objects

```python
import copy

class Student:
    def __init__(self, name, subjects):
        self.name = name
        self.subjects = subjects


s1 = Student("Aamir", ["Math", "Python"])
s2 = copy.copy(s1)
s2.name = "Rahul"
s2.subjects.append("Java")

print(s1.name)       # Aamir
print(s2.name)       # Rahul
print(s1.subjects)   # ['Math', 'Python', 'Java']
print(s2.subjects)   # ['Math', 'Python', 'Java']

print(s1 is s2)                    # False
print(s1.subjects is s2.subjects)  # True
```

- `s2.name = "Rahul"` **rebinds** an attribute on `s2`, a different outer object → `s1` unaffected.
- `s2.subjects.append(...)` **mutates** the list both instances share → `s1` sees it.
- `copy.copy()` on an ordinary instance does **not** call `__init__()` again (custom copy behavior can change this, see Section 6).

## 5. Deep Copy

A **deep copy** creates a new compound object and **recursively copies** the objects it contains. Nested mutable objects get their own copies. Use `copy.deepcopy()`.

### Basic example

```python
import copy

original = [[10, 20], [30, 40]]
deep = copy.deepcopy(original)
deep[0][0] = 999

print(original)   # [[10, 20], [30, 40]]
print(deep)       # [[999, 20], [30, 40]]
```

- `deep[0]` and `original[0]` are **distinct** inner lists, so the original is unchanged.

### Deep copy of class objects

```python
import copy

class Student:
    def __init__(self, name, subjects):
        self.name = name
        self.subjects = subjects


s1 = Student("Aamir", ["Math", "Python"])
s2 = copy.deepcopy(s1)
s2.name = "Rahul"
s2.subjects.append("Java")

print(s1.name)       # Aamir
print(s2.name)       # Rahul
print(s1.subjects)   # ['Math', 'Python']
print(s2.subjects)   # ['Math', 'Python', 'Java']

print(s1 is s2)                    # False
print(s1.subjects is s2.subjects)  # False
```

- Both the outer `Student` and its nested `subjects` list are independent.

### Deep copy does not copy *everything*

```python
import copy

original = [10, "Python", (1, 2)]
deep = copy.deepcopy(original)

print(original is deep)         # False
print(original[0] is deep[0])   # True
```

- The int is **shared**: it's immutable, so sharing it carries no mutation risk.
- Functions and classes are also returned unchanged.
- Some objects (open files, sockets) generally **can't** be deep-copied.

> **Accurate rule:** deep copy recursively reproduces copyable compound state, while letting some objects stay shared according to their type and copy protocol.

## 6. Internals: How `copy` Works

- **`copy.copy(x)`**: uses `x.__copy__()` if defined. Otherwise, for an instance, it builds a new object via `__reduce_ex__` (calls `cls.__new__`, **not** `__init__`) and copies the attribute dict, so attribute values are the **same references**.
- **`copy.deepcopy(x)`**: uses `x.__deepcopy__(memo)` if defined. Otherwise it rebuilds the object and deep-copies each attribute recursively.
- **`memo` dict**: maps `id(original_obj)` → its copy. An object already copied is reused instead of copied again. This preserves shared references inside the structure (Section 8, Case 3) and handles cycles (e.g. a list containing itself).
- **Immutable atomics** (`int`, `str`, `None`, functions, classes) are returned as-is.
- Built-in shortcuts `list.copy()`, `lst[:]`, `dict.copy()` are all **shallow**.

## 7. Shallow Copy vs Deep Copy

| Feature | Shallow copy | Deep copy |
|---|---|---|
| Function | `copy.copy()` | `copy.deepcopy()` |
| New outer object | Generally yes | Generally yes |
| Nested mutable objects | **Shared** | **Recursively copied** |
| Memory usage | Usually lower | Usually higher |
| Speed | Usually faster | Usually slower |
| Nested mutations | Can affect the original | Usually isolated |
| Use when | Nested objects are immutable, or sharing is intended | Independent nested mutable state is required |

### Worked example: assignment vs shallow vs deep

```python
import copy

original = [[10, 20], [30, 40]]
copied = copy.copy(original)  # Try: original, copy.copy(original), copy.deepcopy(original)

copied[0][0] = 99             # Or try: copied.append([50, 60])

print(original)
print(copied)
```

Output for the version shown (shallow copy, nested mutation):

```text
[[99, 20], [30, 40]]
[[99, 20], [30, 40]]
```

| Copy method | Change nested list (`copied[0][0] = 99`) | Append to outer list (`copied.append([50, 60])`) |
|---|---|---|
| Assignment (`copied = original`) | Both change | Both change |
| Shallow (`copy.copy(original)`) | Both change | Only `copied` changes |
| Deep (`copy.deepcopy(original)`) | Only `copied` changes | Only `copied` changes |

## 8. Tricky Cases

### Case 1: Reassignment vs mutation after a shallow copy

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.copy(a)
b[0] = [99, 100]

print(a)   # [[1, 2], [3, 4]]
print(b)   # [[99, 100], [3, 4]]
```

- `b[0] = [99, 100]` **replaces a reference** in the outer list `b`. It doesn't touch the inner list `a[0]` refers to.
- By contrast, `b[0][0] = 99` (while `b[0]` still points to the shared list) **mutates** the shared inner list → `a` changes too.
- **Reassignment** changes what a slot points to; **mutation** changes the object itself.

### Case 2: Shallow copy of a flat list

```python
a = [10, 20, 30]
b = a.copy()
b[0] = 99

print(a)   # [10, 20, 30]
print(b)   # [99, 20, 30]
```

- The outer lists are separate, the elements are immutable ints, and `b[0] = 99` only rebinds a slot in `b`.
- For a flat list of immutable elements, a shallow copy is enough.

### Case 3: Deep copy preserves internal shared references

```python
import copy

shared = [10, 20]
original = [shared, shared]
deep = copy.deepcopy(original)

print(original[0] is original[1])   # True
print(deep[0] is deep[1])           # True
print(original[0] is deep[0])       # False
```

- `deepcopy()` tracks already-copied objects in its **memo** dict. The second time it meets `shared`, it reuses the first copy instead of making another.
- The copy has the **same shape** as the original (one inner list referenced twice). The same mechanism lets it handle many cyclic object graphs.

### Case 4: Is `list.copy()` a deep copy?

No.

```python
a = [[1, 2], [3, 4]]
b = a.copy()
c = a[:]

print(a[0] is b[0])   # True
print(a[0] is c[0])   # True
```

- `.copy()` and slicing `[:]` both make **shallow** copies of lists. `dict.copy()` is also shallow.

## 9. Common Mistakes / Gotchas

- **Writing `name = name` instead of `self.name = name`** → nothing is stored; later access raises `AttributeError`.
- **Defining two `__init__` methods to "overload"** → the second replaces the first. Use default arguments or `@classmethod` alternative constructors.
- **Forgetting `super().__init__()` in a child's `__init__`** → parent attributes are never set → `AttributeError`.
- **Assuming `super()` means "my direct parent"** → it means "next in the MRO"; in a diamond it can call a sibling class.
- **Mixing `Parent.__init__(self)` with `super()` in multiple inheritance** → some classes may be initialized twice or skipped.
- **Assuming `b = a` makes a copy** → it's the same object under another name.
- **Using `list.copy()`, `[:]` or `dict.copy()` on nested data** → shallow; nested mutations leak into the original. Use `copy.deepcopy()`.
- **Confusing reassignment with mutation** → `b[0] = x` doesn't affect a shallow copy's source; `b[0][0] = x` does.
- **Deep copying by default** → more memory and time, duplicates state meant to be shared, can fail on files/sockets.
- **Expecting `copy.copy()` / `deepcopy()` to run `__init__`** → they don't; side effects in `__init__` (counters, logging) won't happen.

## 10. Interview Questions

**Q1. What is the difference between `this` in Java and `self` in Python?**
Java's `this` is a keyword referring to the current object. Python's `self` is an ordinary parameter that receives the current instance by convention; it is not a reserved keyword.

**Q2. Can we use `this()` for constructor chaining in Python?**
No. Python has no Java-style `this()` chaining. Use default arguments, helper methods, or `@classmethod` alternative constructors.

**Q3. What is the difference between `super().__init__()` and `Parent.__init__(self)`?**
`super().__init__()` follows the class's MRO; `Parent.__init__(self)` explicitly calls the named parent's initializer. Cooperative multiple inheritance generally favors `super()`.

**Q4. Does a shallow copy create a separate object?**
For ordinary lists and user-defined instances, yes (a new outer object). But nested mutable objects stay shared, and some immutable or specially handled objects may be returned unchanged.

**Q5. Is deep copy always better than shallow copy?**
No. It costs more memory and time, can duplicate state that should stay shared, and fails on objects that aren't copyable.

**Q6. Does `copy.deepcopy()` create a completely independent copy of every object?**
Not always. It recursively copies supported nested objects, but immutable and specially handled objects may remain shared.

**Q7. What happens when `b = a`?**
`b` refers to the same object as `a`. No new object is created.

## 11. Practice Questions

**1. What does this print?**

```python
import copy

a = [[1, 2], 3, 4]
b = copy.copy(a)
b[0].append(5)
print(a)
```

(a) `[[1, 2], 3, 4]`  (b) `[[1, 2, 5], 3, 4]`  (c) `[[1, 2], 3, 4, 5]`  (d) Error

<details><summary>Answer</summary>

**(b) `[[1, 2, 5], 3, 4]`**: the shallow copy shares the inner list `[1, 2]`, and `append` mutates it, so `a` sees the change.

</details>

**2. What does this print?**

```python
import copy

a = [[1, 2]]
b = copy.deepcopy(a)
b[0].append(3)
print(a)
```

(a) `[[1, 2, 3]]`  (b) `[[1, 2]]`  (c) `[[3]]`  (d) Error

<details><summary>Answer</summary>

**(b) `[[1, 2]]`**: the deep copy has its own inner list, so mutating `b[0]` doesn't affect `a`.

</details>

**3. Which sequence is printed?**

```python
class A:
    def __init__(self):
        print("A")


class B(A):
    def __init__(self):
        print("B")
        super().__init__()


B()
```

(a) A then B  (b) B then A  (c) Only B  (d) Only A

<details><summary>Answer</summary>

**(b) B then A**: `B.__init__` prints `"B"` first, then `super().__init__()` runs `A.__init__`, which prints `"A"`.

</details>

**4. What does this print?**

```python
import copy

a = [[1], 2]
b = copy.copy(a)
b[0] = 99
print(a[0])
```

(a) `99`  (b) `[1]`  (c) `[1, 99]`  (d) Error

<details><summary>Answer</summary>

**(b) `[1]`**: `b[0] = 99` reassigns a slot in the separate outer list `b`; it doesn't mutate the inner list that `a[0]` still refers to.

</details>

## Quick Recap

- **`self`** → the receiving instance; a convention, **not** a keyword. Python has no `this`.
- **`self` vs `cls`** → instance methods get the instance; `@classmethod` methods get the class.
- **No `__init__` overloading** → the last definition wins. Use default args or `@classmethod` alternative constructors (`return cls(...)`).
- **Constructor chaining** → reuse initialization through delegation or `super().__init__()`.
- **`super()`** → follows the **MRO**, supports cooperative initialization; it does **not** create a separate parent object.
- **`b = a`** → another reference to the same object.
- **Shallow copy** (`copy.copy`, `.copy()`, `[:]`) → new outer object, **shared** nested objects.
- **Deep copy** (`copy.deepcopy`) → recursively copies supported nested state; immutables may stay shared; `memo` preserves internal sharing and cycles.
- **Mutation** of a shared mutable object affects every reference to it.
- **Reassignment** of one reference doesn't modify the object it previously pointed to.

> **Core idea:** shallow and deep copies differ in how they handle **nested references**, not in whether they create a new outer object. Understand identity, references and mutation, and most copy questions become straightforward.
