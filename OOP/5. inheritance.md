# Python OOP — Inheritance (Complete Revision Notes)

## 1. What Is Inheritance?

Inheritance is a fundamental concept of Object-Oriented Programming (OOP) that allows one class to acquire the attributes and methods of another class.

**In simple terms:**

Inheritance allows us to create a new class based on an existing class, reuse its functionality, and extend or modify its behavior without rewriting the existing code.

The class being inherited from is called the Parent Class (Base Class or Superclass).

The class that inherits is called the Child Class (Derived Class or Subclass).

### Basic Syntax

```python
class Parent:
    # Parent class implementation
    pass

class Child(Parent):
    # Child class implementation
    pass
```

**Here:**

- Parent is the base class.
- Child is the derived class.
- Child inherits the accessible attributes and methods of Parent.
- Child can define additional attributes and methods.
- Child can override methods inherited from Parent.

### Basic Example

```python
class Animal:
    def eat(self):
        print("Animal is eating")

class Dog(Animal):
    def bark(self):
        print("Dog is barking")

dog = Dog()
dog.eat()
dog.bark()
```

**Output:**

```text
Animal is eating
Dog is barking
```

**Explanation**

The Dog class defines only the `bark()` method.

However, because Dog inherits from Animal, its objects can also access the `eat()` method.

**When Python executes:**

```python
dog.eat()
```

It searches for eat according to Python’s attribute lookup rules, which include searching the parent classes.

Since Animal defines `eat()`, Python finds that method and executes it.

**Important:** Inheritance does not mean Python physically copies all parent methods into the child class. Instead, Python uses the class hierarchy and Method Resolution Order (MRO) to find inherited attributes and methods.

## 2. Why Do We Need Inheritance?

Inheritance primarily solves the problem of code duplication and provides a way to model relationships between classes.

### Without Inheritance

```python
class Dog:
    def eat(self):
        print("Eating")
    def sleep(self):
        print("Sleeping")
    def bark(self):
        print("Barking")

class Cat:
    def eat(self):
        print("Eating")
    def sleep(self):
        print("Sleeping")
    def meow(self):
        print("Meowing")
```

### Problems

Both classes implement the same `eat()` and `sleep()` methods.

**This creates:**

- Code duplication.
- Increased maintenance effort.
- More opportunities for inconsistent behavior.
- Difficulty extending shared functionality.

### With Inheritance

```python
class Animal:
    def eat(self):
        print("Eating")
    def sleep(self):
        print("Sleeping")

class Dog(Animal):
    def bark(self):
        print("Barking")

class Cat(Animal):
    def meow(self):
        print("Meowing")
```

Now, `eat()` and `sleep()` are defined only once.

Both Dog and Cat reuse these methods through inheritance.

### Advantages of Inheritance

| Advantage | Explanation |
| --- | --- |
| Code reusability | Reuse existing functionality without rewriting it |
| Reduced duplication | Common functionality can be defined in a base class |
| Extensibility | Child classes can add new functionality |
| Method overriding | Child classes can customize inherited behavior |
| Polymorphism | Different subclasses can be used through a common interface |
| Maintainability | Shared behavior can be maintained centrally |
| Logical organization | Related classes can form meaningful hierarchies |

**Important:** Inheritance should not be used only to reduce code duplication. The child class should represent a meaningful specialization of the parent class.

## 3. Understanding the IS-A Relationship

Inheritance generally represents an IS-A relationship.

**For example:**

- A Dog is an Animal.
- A Car is a Vehicle.
- A Manager is an Employee.

**Consider:**

```python
class Vehicle:
    def start(self):
        print("Vehicle started")

class Car(Vehicle):
    pass

class Bike(Vehicle):
    pass
```

**Here:**

- Car IS-A Vehicle.
- Bike IS-A Vehicle.

Therefore, inheritance is appropriate.

### When Inheritance Is Not Appropriate

**Consider:**

- A Car has an Engine.
- A Library has Books.
- A Computer has a Processor.

These are HAS-A relationships, usually better represented using composition.

```python
class Engine:
    def start(self):
        print("Engine started")

class Car:
    def __init__(self):
        self.engine = Engine()
    def start(self):
        self.engine.start()

car = Car()
car.start()
```

**Output:**

```text
Engine started
```

Here, Car contains an Engine instead of inheriting from it.

### Inheritance vs Composition

| Inheritance | Composition |
| --- | --- |
| Represents IS-A | Represents HAS-A |
| Uses subclassing | Uses object references |
| Reuses behavior through a class hierarchy | Reuses behavior through contained objects |
| Creates tighter coupling | Often provides greater flexibility |
| Can override inherited methods | Can replace or delegate to contained components |

**Rule of thumb:** Prefer inheritance when the child can legitimately be treated as an instance of the parent. Prefer composition when one object uses or contains another.

## 4. Types of Inheritance in Python

Python supports several inheritance structures.

### 4.1 Single Inheritance

A child class inherits from one parent class.

Dog inherits from Animal. The arrow points toward the parent.

```python
class Animal:
    def eat(self):
        print("Eating")

class Dog(Animal):
    def bark(self):
        print("Barking")

dog = Dog()
dog.eat()
dog.bark()
```

**Output:**

```text
Eating
Barking
```

### 4.2 Multilevel Inheritance

A class inherits from a class that itself inherits from another class.

```python
class Animal:
    def eat(self):
        print("Eating")

class Mammal(Animal):
    def walk(self):
        print("Walking")

class Dog(Mammal):
    def bark(self):
        print("Barking")

dog = Dog()
dog.eat()
dog.walk()
dog.bark()
```

**Output:**

```text
Eating
Walking
Barking
```

The Dog class has access to methods defined in both Mammal and Animal.

**The inheritance chain is:**

`Dog -> Mammal -> Animal -> object`

### 4.3 Hierarchical Inheritance

Multiple child classes inherit from the same parent class.

```python
class Animal:
    def eat(self):
        print("Eating")

class Dog(Animal):
    def bark(self):
        print("Barking")

class Cat(Animal):
    def meow(self):
        print("Meowing")

class Cow(Animal):
    def moo(self):
        print("Mooing")
```

All three subclasses inherit `eat()`.

However, Dog does not automatically inherit methods defined in Cat or Cow.

### 4.4 Multiple Inheritance

A child class inherits from more than one parent class.

```python
class Father:
    def skills(self):
        print("Gardening")

class Mother:
    def hobbies(self):
        print("Painting")

class Child(Father, Mother):
    pass

child = Child()
child.skills()
child.hobbies()
```

**Output:**

```text
Gardening
Painting
```

The Child class inherits functionality from both parents.

When multiple parents define the same attribute or method, Python uses the Method Resolution Order (MRO) to decide which implementation to use.

We will examine MRO in detail later.

### 4.5 Hybrid Inheritance

Hybrid inheritance combines two or more inheritance structures.

**For example, combining hierarchical and multiple inheritance:**

#### Diamond-shaped hybrid inheritance

```python
class A:
    def method_a(self):
        print("Method A")

class B(A):
    def method_b(self):
        print("Method B")

class C(A):
    def method_c(self):
        print("Method C")

class D(B, C):
    def method_d(self):
        print("Method D")

obj = D()
obj.method_a()
obj.method_b()
obj.method_c()
obj.method_d()
```

**Output:**

```text
Method A
Method B
Method C
Method D
```

Notice that both B and C inherit from A.

This creates a diamond-shaped inheritance hierarchy.

Python handles method lookup in this structure using C3 linearization.

## 5. How Inheritance Works Internally in Python

Understanding the internal working of inheritance is important.

**Consider:**

```python
class Parent:
    def show(self):
        print("Parent method")

class Child(Parent):
    pass

obj = Child()
obj.show()
```

**When Python executes:**

```python
obj.show()
```

**Conceptually:**

- Python looks up the attribute show on the object, considering descriptors and the object’s class.
- Since Child does not define show, Python continues through its inheritance hierarchy.
- Python finds show in Parent.
- It binds that function to obj as an instance method.
- The method executes with self referring to obj.

The exact attribute lookup process also involves instance attributes, class dictionaries, and descriptor precedence. The crucial point is that inherited methods are located through the class hierarchy, not copied into every child class.

### Inspecting Class Dictionaries

```python
class Parent:
    def show(self):
        print("Parent method")

class Child(Parent):
    pass

print("show" in Parent.__dict__)
print("show" in Child.__dict__)
```

**Output:**

```text
True
False
```

The show method physically exists in the namespace of Parent, not Child.

**Nevertheless:**

```python
child = Child()
print(hasattr(child, "show"))
```

**Output:**

```text
True
```

This is because show is inherited.

### Inspecting Direct Parent Classes

```python
print(Child.__bases__)
```

**Output:**

```text
(<class '__main__.Parent'>,)
```

`__bases__` contains the direct base classes of a class.

### Inspecting the Full Inheritance Hierarchy

```python
print(Child.__mro__)
```

**Output:**

```text
(<class '__main__.Child'>,
 <class '__main__.Parent'>,
 <class 'object'>)
```

The displayed class representations may vary depending on the module in which the classes are defined.

## 6. Constructors and Inheritance

A constructor-related concept in Python is the `__init__()` method.

Technically, `__init__()` is an initializer, not the method that creates the object. Object creation is primarily handled by `__new__()`.

For ordinary inheritance examples, understanding `__init__()` is the most important part.

### 6.1 Child Class Without Its Own __init__()

```python
class Parent:
    def __init__(self):
        print("Parent initializer")

class Child(Parent):
    pass

obj = Child()
```

**Output:**

```text
Parent initializer
```

**Why?**

Child does not implement `__init__()`.

Therefore, Python finds the inherited `Parent.__init__()` method and calls it.

**Rule:** If the child does not define `__init__()`, it normally inherits the parent’s initializer.

### 6.2 Child Class Defines Its Own __init__()

```python
class Parent:
    def __init__(self):
        print("Parent initializer")

class Child(Parent):
    def __init__(self):
        print("Child initializer")

obj = Child()
```

**Output:**

```text
Child initializer
```

**Explanation**

The child defines its own `__init__()`.

Therefore, the child’s initializer overrides the parent’s initializer.

Python does not automatically execute the parent initializer after the child’s initializer.

This becomes important when the parent initializer creates attributes needed by inherited methods.

### 6.3 Calling the Parent Initializer Using super()

```python
class Parent:
    def __init__(self):
        print("Parent initializer")

class Child(Parent):
    def __init__(self):
        super().__init__()
        print("Child initializer")

obj = Child()
```

**Output:**

```text
Parent initializer
Child initializer
```

`super().__init__()` delegates initialization to the next appropriate class in the MRO.

In this simple inheritance hierarchy, that is Parent.

#### Real-World Example

```python
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary
    def display(self):
        print(f"Name: {self.name}")
        print(f"Salary: {self.salary}")

class Manager(Employee):
    def __init__(self, name, salary, department):
        super().__init__(name, salary)
        self.department = department
    def show_department(self):
        print(f"Department: {self.department}")

manager = Manager("Aamir", 80000, "Engineering")
manager.display()
manager.show_department()
```

**Output:**

```text
Name: Aamir
Salary: 80000
Department: Engineering
```

#### Execution Flow

**When the following executes:**

```python
manager = Manager("Aamir", 80000, "Engineering")
```

- Python creates the Manager instance through the object-creation process.
- Python invokes `Manager.__init__()`.
- `Manager.__init__()` executes `super().__init__(name, salary)`.
- `Employee.__init__()` initializes name and salary.
- Execution returns to `Manager.__init__()`.
- department is initialized.
- Initialization finishes.

The result is one Manager object containing all three instance attributes.

#### Common Mistake: Forgetting `super().__init__()`

```python
class Parent:
    def __init__(self):
        self.name = "Python"

class Child(Parent):
    def __init__(self):
        self.age = 25

obj = Child()
print(obj.name)
```

**Error:**

```text
AttributeError: 'Child' object has no attribute 'name'
```

The child initializer did not initialize name.

**Correct implementation:**

```python
class Child(Parent):
    def __init__(self):
        super().__init__()
        self.age = 25
```

**Important:** Calling `super().__init__()` is not universally mandatory, but it is generally appropriate when extending a parent initializer. In cooperative multiple inheritance, correctly calling `super()` is especially important.

## 7. Method Overriding in Inheritance

Method overriding occurs when a child class defines a method with the same name as a method inherited from its parent.

It allows the child class to provide a specialized implementation.

**Example**

```python
class Animal:
    def sound(self):
        print("Animals make sounds")

class Dog(Animal):
    def sound(self):
        print("Dog barks")

dog = Dog()
dog.sound()
```

**Output:**

```text
Dog barks
```

**Explanation**

Both Animal and Dog define `sound()`.

When `dog.sound()` is called, the Dog implementation takes precedence.

Python resolves the method at runtime based on the object’s class and the attribute lookup rules.

### 7.1 Extending an Overridden Method

Sometimes we want to preserve the parent behavior and add new functionality.

```python
class Animal:
    def sound(self):
        print("Animal sound")

class Dog(Animal):
    def sound(self):
        super().sound()
        print("Dog barks")

dog = Dog()
dog.sound()
```

**Output:**

```text
Animal sound
Dog barks
```

**Here:**

- `super().sound()` invokes the next implementation in the MRO.
- The child then executes its additional behavior.

This pattern is useful when customizing existing functionality without completely replacing it.

### 7.2 Can We Call the Parent Method Directly?

Yes.

```python
class Parent:
    def show(self):
        print("Parent")

class Child(Parent):
    def show(self):
        Parent.show(self)
        print("Child")

Child().show()
```

**Output:**

```text
Parent
Child
```

**However, there is an important difference:**

```python
Parent.show(self)
```

Explicitly calls the Parent implementation.

**Whereas:**

```python
super().show()
```

Looks for the next implementation in the MRO.

This distinction becomes especially important in multiple inheritance, where directly calling a particular parent may skip other classes or execute shared ancestors more than once.

## 8. Understanding super() in Depth

One of the most commonly misunderstood concepts in Python inheritance is `super()`.

**Many beginners learn:**

`super()` calls the parent class.

That explanation is useful for simple cases, but it is incomplete.

**A more accurate definition is:**

`super()` creates a proxy that delegates attribute lookup to the next applicable class in the Method Resolution Order (MRO).

**Example**

```python
class A:
    def show(self):
        print("A")

class B(A):
    def show(self):
        print("B")
        super().show()

class C(B):
    def show(self):
        print("C")
        super().show()

obj = C()
obj.show()
```

**Output:**

```text
C
B
A
```

**The MRO is:**

`C -> B -> A -> object`

**So:**

- `C.show()` runs.
- `super().show()` inside C finds `B.show()`.
- `super().show()` inside B finds `A.show()`.

### Two Forms of `super()`

```python
super()
```

This is the usual Python 3 form inside instance methods and class methods.

**The explicit form is:**

```python
super(CurrentClass, obj)
```

**For example:**

```python
class Parent:
    def show(self):
        print("Parent")

class Child(Parent):
    def show(self):
        super(Child, self).show()
```

In this example, both forms behave the same.

**For normal Python 3 code, prefer:**

```python
super().method()
```

### Important Properties of `super()`

- It is not a reference to a fixed parent class.
- It follows the current class’s MRO.
- It supports cooperative multiple inheritance.
- It can invoke overridden methods and initializers.
- It does not automatically invoke every parent initializer unless the inheritance chain cooperates.
- It is typically used to extend inherited methods while preserving their functionality.

## 9. Method Resolution Order (MRO)

MRO stands for Method Resolution Order.

It determines the order in which Python searches classes when resolving inherited attributes and methods.

Python uses the C3 linearization algorithm to compute the MRO for standard classes.

### 9.1 MRO in Single Inheritance

```python
class A:
    pass

class B(A):
    pass

class C(B):
    pass

print([cls.__name__ for cls in C.mro()])
```

**Output:**

```text
['C', 'B', 'A', 'object']
```

Python searches according to this linearized hierarchy.

### 9.2 MRO in Multiple Inheritance

```python
class A:
    def show(self):
        print("A")

class B:
    def show(self):
        print("B")

class C(A, B):
    pass

obj = C()
obj.show()
```

**Output:**

```text
A
```

**Why?**

```python
print([cls.__name__ for cls in C.mro()])
```

**Output:**

```text
['C', 'A', 'B', 'object']
```

The A implementation appears before the B implementation in the MRO.

**If we change the declaration:**

```python
class C(B, A):
    pass
```

**Then the MRO becomes:**

`C -> B -> A -> object`

Now `C().show()` executes `B.show()`.

Note: The order of base classes matters, but MRO is not simply a universal left-to-right depth-first traversal. C3 also preserves ordering constraints imposed by parent hierarchies.

## 10. The Diamond Problem

The diamond problem occurs when a class inherits from multiple classes that share a common ancestor.

**Consider:**

```text
        A
       / \
      B   C
       \ /
        D
```

**Here:**

- B inherits from A.
- C inherits from A.
- D inherits from both B and C.

The problem is determining how Python should resolve methods and avoid executing shared ancestor behavior multiple times unnecessarily.

**Example**

```python
class A:
    def show(self):
        print("A")
        super().show()

class B(A):
    def show(self):
        print("B")
        super().show()

class C(A):
    def show(self):
        print("C")
        super().show()

class D(B, C):
    def show(self):
        print("D")
        super().show()
```

This example would eventually reach object, which does not provide `show()`.

To complete the cooperative chain safely, let the root implementation stop the delegation:

```python
class A:
    def show(self):
        print("A")

class B(A):
    def show(self):
        print("B")
        super().show()

class C(A):
    def show(self):
        print("C")
        super().show()

class D(B, C):
    def show(self):
        print("D")
        super().show()

obj = D()
obj.show()
```

**Output:**

```text
D
B
C
A
```

**Inspect the MRO:**

```python
print([cls.__name__ for cls in D.mro()])
```

**Output:**

```text
['D', 'B', 'C', 'A', 'object']
```

Why Is the Output D → B → C → A?

The crucial point is that `super()` follows the MRO of the actual class hierarchy.

**When `B.show()` calls:**

```python
super().show()
```

The next class after B in D’s MRO is C, not A.

So `C.show()` executes next.

Only after C does Python reach A.

This is why understanding `super()` as simply “call my parent” is incorrect in multiple inheritance.

What Does C3 Linearization Guarantee?

**C3 preserves three important properties:**

- Local precedence ordering: The order in which direct base classes are declared is respected.
- Monotonicity: A subclass preserves the relative ordering constraints established by its parents.
- Consistency: Each class appears only once in the resulting MRO.

Can Python Reject an Inheritance Hierarchy?

Yes.

```python
class A:
    pass

class B:
    pass

class X(A, B):
    pass

class Y(B, A):
    pass

class Z(X, Y):
    pass
```

**Error:**

```text
TypeError: Cannot create a consistent method resolution
order (MRO) for bases A, B
```

The exact error wording may vary by Python version.

**Why?**

- X requires A to appear before B.
- Y requires B to appear before A.
- Z tries to combine these incompatible requirements.

Python cannot compute a consistent MRO.

## 11. Cooperative Multiple Inheritance

Multiple inheritance works best when all relevant classes follow a cooperative method-calling convention using `super()`.

This is particularly important for initializers.

**Example**

```python
class Base:
    def __init__(self, **kwargs):
        super().__init__(**kwargs)

class LoggingMixin:
    def __init__(self, *, logging=False, **kwargs):
        self.logging = logging
        super().__init__(**kwargs)

class ValidationMixin:
    def __init__(self, *, validate=False, **kwargs):
        self.validate = validate
        super().__init__(**kwargs)

class Service(LoggingMixin, ValidationMixin, Base):
    def __init__(self, name, **kwargs):
        self.name = name
        super().__init__(**kwargs)

service = Service(
    "PaymentService",
    logging=True,
    validate=True
)
print(service.name)
print(service.logging)
print(service.validate)
```

**Output:**

```text
PaymentService
True
True
```

**MRO**

```python
print([cls.__name__ for cls in Service.mro()])
```

**Output:**

```text
[
    'Service',
    'LoggingMixin',
    'ValidationMixin',
    'Base',
    'object'
]
```

**Explanation**

Each initializer consumes the arguments it needs and passes remaining keyword arguments to the next class.

**The initialization chain is:**

```text
Service.__init__()
       |
       v
LoggingMixin.__init__()
       |
       v
ValidationMixin.__init__()
       |
       v
Base.__init__()
       |
       v
object.__init__()
```

`object.__init__()` does not accept arbitrary application-specific keyword arguments, so the cooperative chain must consume them before reaching object.

**Key principle:** Cooperative multiple inheritance requires participating classes to have compatible method signatures and consistently delegate using `super()`.

## 12. Inheritance and Polymorphism

Inheritance enables an important OOP concept called polymorphism.

Polymorphism means that different objects can respond to the same operation in different ways.

**Example**

```python
class Animal:
    def speak(self):
        print("Animal sound")

class Dog(Animal):
    def speak(self):
        print("Bark")

class Cat(Animal):
    def speak(self):
        print("Meow")

animals = [
    Animal(),
    Dog(),
    Cat()
]
for animal in animals:
    animal.speak()
```

**Output:**

```text
Animal sound
Bark
Meow
```

**The same method call:**

```python
animal.speak()
```

produces different behavior depending on the object’s actual class.

This is runtime polymorphism through method overriding.

### Dynamic Dispatch

**Consider:**

```python
class Shape:
    def describe(self):
        print(f"Area: {self.area()}")
    def area(self):
        return 0

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height
    def area(self):
        return self.width * self.height

rectangle = Rectangle(10, 5)
rectangle.describe()
```

**Output:**

```text
Area: 50
```

Notice that `describe()` is defined in Shape.

**Inside it:**

```python
self.area()
```

Because self refers to a Rectangle instance, Python resolves `area()` to `Rectangle.area()`.

This demonstrates dynamic dispatch: an inherited method can call a method overridden by a subclass.

### Important Python Detail

Python also supports polymorphism without inheritance through duck typing.

If unrelated objects provide compatible methods, Python can often use them interchangeably.

Therefore, inheritance is one mechanism for polymorphism, not the only one.

## 13. isinstance() and issubclass()

Python provides two useful built-in functions for working with inheritance hierarchies.

### 13.1 isinstance()

Checks whether an object is an instance of a class or a subclass of that class.

```python
class Animal:
    pass

class Dog(Animal):
    pass

dog = Dog()
print(isinstance(dog, Dog))
print(isinstance(dog, Animal))
print(isinstance(dog, object))
```

**Output:**

```text
True
True
True
```

dog is directly an instance of Dog.

Since Dog inherits from Animal, it is also considered an instance of Animal.

All ordinary Python classes ultimately inherit from object.

### 13.2 issubclass()

Checks whether one class is a subclass of another.

```python
print(issubclass(Dog, Animal))
print(issubclass(Animal, Dog))
print(issubclass(Dog, object))
print(issubclass(Dog, Dog))
```

**Output:**

```text
True
False
True
True
```

#### Difference Between `type()` and `isinstance()`

```python
class Animal:
    pass

class Dog(Animal):
    pass

dog = Dog()
print(type(dog) is Animal)
print(isinstance(dog, Animal))
```

**Output:**

```text
False
True
```

`type(dog)` returns the exact runtime class, Dog.

`isinstance(dog, Animal)` accounts for inheritance.

In many inheritance-aware checks, `isinstance()` is preferable to exact type comparisons.

## 14. Inheritance of Class and Instance Attributes

Methods are not the only things affected by inheritance.

Class attributes and instance initialization behavior also participate.

### 14.1 Inheriting Class Attributes

```python
class Parent:
    language = "Python"

class Child(Parent):
    pass

obj = Child()
print(obj.language)
print(Child.language)
```

**Output:**

```text
Python
Python
```

The class attribute is found through inheritance.

### 14.2 Overriding Class Attributes

```python
class Parent:
    language = "Python"

class Child(Parent):
    language = "Java"

print(Parent.language)
print(Child.language)
```

**Output:**

```text
Python
Java
```

The child defines its own class attribute, shadowing the inherited value.

The parent remains unchanged.

### 14.3 Instance Attribute Shadowing

```python
class Parent:
    value = 100

class Child(Parent):
    pass

obj = Child()
obj.value = 200
print(obj.value)
print(Child.value)
print(Parent.value)
```

**Output:**

```text
200
100
100
```

**Explanation:**

```python
obj.value = 200
```

creates an instance attribute named value.

It does not change the inherited class attribute.

#### **Important:** Mutable Class Attributes

```python
class Parent:
    items = []

class Child(Parent):
    pass

a = Child()
b = Child()
a.items.append("Python")
print(b.items)
print(Parent.items)
```

**Output:**

```text
['Python']
['Python']
```

**Why?**

Both objects find the same inherited mutable class attribute.

This is a common source of bugs.

**If each object needs its own list, initialize it as an instance attribute:**

```python
class Parent:
    def __init__(self):
        self.items = []

class Child(Parent):
    pass
```

Now every new instance receives its own list.

## 15. Access Modifiers and Inheritance

Python does not enforce traditional Java-style public, protected, and private access modifiers.

Instead, it relies primarily on naming conventions and name mangling.

### 15.1 Public Members

Public members have ordinary names.

```python
class Parent:
    def __init__(self):
        self.name = "Python"

class Child(Parent):
    def display(self):
        print(self.name)

Child().display()
```

**Output:**

```text
Python
```

Public members are intended for normal access.

### 15.2 Protected Convention: Single Underscore

A name beginning with a single underscore indicates internal or non-public use by convention.

```python
class Parent:
    def __init__(self):
        self._salary = 50000

class Child(Parent):
    def display(self):
        print(self._salary)

Child().display()
```

**Output:**

```text
50000
```

Python does not prohibit access to _salary.

The underscore tells developers that the attribute is intended for internal use.

### 15.3 Double Underscore and Name Mangling

```python
class Parent:
    def __init__(self):
        self.__secret = "Hidden"

class Child(Parent):
    def display(self):
        print(self.__secret)

Child().display()
```

**Error:**

```text
AttributeError: 'Child' object has no attribute '_Child__secret'
```

**Why?**

Python applies name mangling to identifiers beginning with at least two underscores and ending with fewer than two underscores.

**Inside Parent:**

```python
self.__secret
```

**is transformed to a name similar to:**

```python
self._Parent__secret
```

**Inside Child, the same written identifier becomes:**

```python
self._Child__secret
```

Those are different attribute names.

#### Accessing the Mangled Attribute

```python
class Parent:
    def __init__(self):
        self.__secret = "Hidden"

class Child(Parent):
    def display(self):
        print(self._Parent__secret)

Child().display()
```

**Output:**

```text
Hidden
```

This works, but directly depending on another class’s mangled attribute is generally discouraged.

#### Better Approach: Expose a Method or Property

```python
class Parent:
    def __init__(self):
        self.__secret = "Hidden"
    @property
    def secret(self):
        return self.__secret

class Child(Parent):
    def display(self):
        print(self.secret)

Child().display()
```

**Output:**

```text
Hidden
```

**Important:** Double underscores do not provide true security or absolute privacy. Name mangling mainly helps prevent accidental naming conflicts in subclasses.

## 16. Abstract Classes and Inheritance

Sometimes a base class should define a common contract without allowing itself to be instantiated directly.

Python supports this using abstract base classes.

**We use:**

```python
from abc import ABC, abstractmethod
```

**Example**

```python
from abc import ABC, abstractmethod
class Shape(ABC):
    @abstractmethod
    def area(self):
        pass

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius
    def area(self):
        return 3.14 * self.radius ** 2

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width = width
        self.height = height
    def area(self):
        return self.width * self.height

circle = Circle(5)
rectangle = Rectangle(10, 4)
print(circle.area())
print(rectangle.area())
```

**Output:**

```text
78.5
40
```

Why Use Abstract Classes?

Shape defines a contract requiring concrete subclasses to implement `area()`.

**Attempting:**

```python
shape = Shape()
```

raises a TypeError, because Shape contains an unimplemented abstract method.

**Similarly:**

```python
class Triangle(Shape):
    pass
triangle = Triangle()
```

raises a TypeError because Triangle has not implemented the required `area()` method.

### Important Details

- Abstract base classes can contain concrete methods.
- Abstract methods can have implementations, though concrete subclasses must still satisfy abstract-method requirements.
- A subclass remains abstract while required abstract methods remain unimplemented.
- Abstract classes are useful for defining shared contracts across related subclasses.

Abstract classes connect inheritance with abstraction and polymorphism.

## 17. Inheriting and Overriding Different Method Types

Python supports instance methods, class methods, static methods, and properties.

All can participate in inheritance.

### 17.1 Instance Methods

```python
class Parent:
    def show(self):
        print("Parent")

class Child(Parent):
    def show(self):
        print("Child")

Child().show()
```

**Output:**

```text
Child
```

### 17.2 Class Methods

Class methods receive cls instead of self.

```python
class Animal:
    @classmethod
    def create(cls):
        return cls()

class Dog(Animal):
    pass

dog = Dog.create()
print(type(dog).__name__)
```

**Output:**

```text
Dog
```

**Why?**

The inherited class method receives Dog as cls when called through Dog.

**Therefore:**

```python
return cls()
```

creates a Dog instance.

This makes class methods useful for polymorphic factory methods.

### 17.3 Static Methods

```python
class Parent:
    @staticmethod
    def greet():
        print("Hello")

class Child(Parent):
    pass
Child.greet()
```

**Output:**

```text
Hello
```

Static methods can be inherited just like ordinary class attributes.

They do not automatically receive self or cls.

### 17.4 Properties

```python
class Person:
    def __init__(self, name):
        self._name = name
    @property
    def name(self):
        return self._name

class Employee(Person):
    pass

employee = Employee("Aamir")
print(employee.name)
```

**Output:**

```text
Aamir
```

The property descriptor is inherited.

A child class can also override the property to customize how the attribute is accessed.

## 18. Mixins in Python

A mixin is a class designed to provide reusable functionality to other classes, typically through multiple inheritance.

Unlike a regular domain base class, a mixin usually represents a capability rather than a complete IS-A relationship.

**Common examples include:**

- Logging capability.
- Serialization capability.
- Validation capability.
- Permission checking.

**Example**

```python
class LoggingMixin:
    def log(self, message):
        print(f"[LOG] {message}")

class SerializationMixin:
    def serialize(self):
        return self.__dict__.copy()

class User(LoggingMixin, SerializationMixin):
    def __init__(self, name, age):
        self.name = name
        self.age = age

user = User("Aamir", 25)
user.log("User created")
print(user.serialize())
```

**Output:**

```text
[LOG] User created
{'name': 'Aamir', 'age': 25}
```

### Why Mixins Are Useful

Rather than building complex inheritance hierarchies, mixins let classes combine focused capabilities.

**For example:**

```python
class AdminUser(LoggingMixin, SerializationMixin):
    pass
```

This class receives both capabilities.

### Best Practices for Mixins

- Keep mixins focused on one capability.
- Avoid unnecessary dependencies on unrelated attributes.
- Document attributes and methods required from consuming classes.
- Use cooperative `super()` calls when overriding methods shared across a multiple-inheritance hierarchy.
- Avoid deeply nested or confusing combinations of mixins.

## 19. Every Python Class Ultimately Inherits From object

In Python 3, a normal class without an explicitly declared parent inherits from object.

**These declarations are effectively equivalent:**

```python
class A:
    pass

class A(object):
    pass
```

**Example**

```python
class A:
    pass

print(A.__bases__)
print(A.__mro__)
```

**Output:**

```text
(<class 'object'>,)
(<class '__main__.A'>, <class 'object'>)
```

The object class provides basic behavior used throughout Python’s object model.

**For example, it provides default implementations for methods such as:**

`__new__()`
`__init__()`
`__str__()`
`__repr__()`
`__eq__()`
`__hash__()`

Some of these methods can be overridden by subclasses.

### Example: Overriding `__str__()`

```python
class Employee:
    def __init__(self, name):
        self.name = name

employee = Employee("Aamir")

```

**Output:**

```text

```

Without an appropriate `__str__()` implementation, the default representation typically includes the object’s class and an implementation-dependent identity-related value.

## 20. Inheritance and Special Methods

Special methods, also called dunder methods, participate in inheritance.

**Examples:**

`__init__()`
`__str__()`
`__repr__()`
`__len__()`
`__eq__()`
`__add__()`

**However, Python has an important lookup rule:**

Many implicit operations look up special methods on the object’s type, not directly in the instance dictionary.

**Example**

```python
class Parent:
    def __len__(self):
        return 5

class Child(Parent):
    pass

obj = Child()
print(len(obj))
```

**Output:**

```text
5
```

The inherited special method is used by `len()`.

### Instance-Level Override Does Not Necessarily Affect Special Syntax

```python
class MyClass:
    def __len__(self):
        return 5

obj = MyClass()
obj.__len__ = lambda: 100
print(obj.__len__())
print(len(obj))
```

**Output:**

```text
100
5
```

**Why?**

**A direct call:**

```python
obj.__len__()
```

performs ordinary attribute access and finds the instance attribute.

**But:**

```python
len(obj)
```

uses the special-method lookup mechanism, which finds `__len__` on the object’s class hierarchy.

This is an advanced but important part of Python’s object model.

## 21. The Liskov Substitution Principle (LSP)

The Liskov Substitution Principle is an important design principle connected to inheritance.

**It states, informally:**

Objects of a subtype should be usable wherever objects of the base type are expected, without violating the expectations of the program.

This is more than simply making `isinstance(child, Parent)` return True.

The subclass must preserve the relevant behavioral contract.

### Good Example

```python
class Bird:
    def eat(self):
        print("Eating")

class Sparrow(Bird):
    def fly(self):
        print("Flying")

class Penguin(Bird):
    def swim(self):
        print("Swimming")
```

This is reasonable because both sparrows and penguins are birds, and the shared Bird contract does not require flying.

### Problematic Design

```python
class Bird:
    def fly(self):
        print("Flying")

class Penguin(Bird):
    def fly(self):
        raise NotImplementedError("Penguins cannot fly")
```

This can violate substitutability if client code expects every Bird to be able to fly.

### Improved Design

```python
class Bird:
    def eat(self):
        print("Eating")

class FlyingBird(Bird):
    def fly(self):
        print("Flying")

class Sparrow(FlyingBird):
    pass

class Penguin(Bird):
    def swim(self):
        print("Swimming")
```

Now the hierarchy expresses the actual capabilities more accurately.

### Key Lesson

Inheritance should model valid substitutable relationships, not just superficially similar objects.

A poorly designed parent class can force subclasses to inherit behavior that does not make sense for them.

## 22. Common Mistakes in Inheritance

### Mistake 1: Forgetting Parent Initialization

```python
class Parent:
    def __init__(self):
        self.x = 10

class Child(Parent):
    def __init__(self):
        self.y = 20
```

Child does not automatically initialize x.

**When required, fix this using:**

```python
super().__init__()
```

### Mistake 2: Assuming `super()` Always Calls the Direct Parent

In multiple inheritance, `super()` follows MRO.

The next implementation is not necessarily found in the lexically declared parent of the current class.

### Mistake 3: Calling Multiple Parent Initializers Directly

```python
class A:
    def __init__(self):
        print("A")

class B(A):
    def __init__(self):
        A.__init__(self)

class C(A):
    def __init__(self):
        A.__init__(self)

class D(B, C):
    def __init__(self):
        B.__init__(self)
        C.__init__(self)

D()
```

**Output:**

```text
A
A
```

The shared ancestor’s initializer executes twice.

In more complex systems, this can cause duplicated initialization or inconsistent state.

Cooperative `super()` is generally the preferred approach when designing a multiple-inheritance hierarchy.

### Mistake 4: Confusing Method Overriding with Method Overloading

**Method overriding:**

```python
class A:
    def show(self):
        print("A")

class B(A):
    def show(self):
        print("B")
```

Method overloading traditionally means having multiple methods with the same name but different parameter signatures.

Python does not support Java-style signature-based method overloading through repeated method definitions.

**For example:**

```python
class Calculator:
    def add(self, a, b):
        return a + b
    def add(self, a, b, c):
        return a + b + c
```

The second `add()` replaces the first in the class namespace.

Python can provide flexible alternatives using default arguments, `*args`, dispatch mechanisms, or `functools.singledispatchmethod`.

### Mistake 5: Assuming Double Underscore Means Strict Privacy

Double-underscore attributes are name-mangled, not made completely inaccessible.

### Mistake 6: Using Inheritance Only for Code Reuse

Two unrelated classes might share code, but that does not necessarily justify inheritance.

Composition or a standalone helper function may be more appropriate.

## 23. Inheritance with Dataclasses

Python’s dataclasses module introduces additional inheritance considerations.

**Example**

```python
from dataclasses import dataclass
@dataclass
class Employee:
    name: str
    salary: int

@dataclass
class Manager(Employee):
    department: str

manager = Manager(
    name="Aamir",
    salary=80000,
    department="Engineering"
)
print(manager)
```

**Output:**

```text
Manager(name='Aamir', salary=80000, department='Engineering')
```

The generated initializer includes inherited dataclass fields.

### Important Dataclass Rules

- Fields from dataclass base classes participate in generated subclass methods.
- Non-default fields generally cannot follow default-valued fields in the generated positional parameter order.
- A generated dataclass `__init__()` does not automatically call an arbitrary base class’s custom `__init__()`.
- When custom base initialization is needed, it can sometimes be invoked through `__post_init__()`.

Dataclass inheritance should therefore be considered separately from ordinary class initialization when designing production code.

## 24. When Should You Use Inheritance?

**Use inheritance when:**

- A genuine IS-A relationship exists.
- Subclasses share a meaningful behavioral contract.
- Specialized classes need to override or extend base behavior.
- Polymorphism through a shared parent interface is valuable.
- A stable, understandable class hierarchy can be maintained.

**Avoid inheritance when:**

- You only want to reuse a few unrelated helper methods.
- The relationship is HAS-A rather than IS-A.
- Subclasses require many exceptions to the parent’s behavior.
- The hierarchy becomes too deep or difficult to understand.
- Changes in the parent frequently break otherwise unrelated subclasses.

### Practical Design Comparison

| Situation | Recommended Design |
| --- | --- |
| Dog and Animal | Inheritance |
| Car and Engine | Composition |
| Manager and Employee | Inheritance, if the employee contract applies |
| User and Logging | Mixin or composition |
| Order and PaymentProcessor | Composition |
| Circle and Shape | Inheritance |
| Two unrelated classes sharing a utility function | Function or composition |

**A useful principle in object-oriented design is:**

Favor composition over inheritance when a class relationship does not clearly require specialization.

## 25. Complete Real-World Example

Let’s combine inheritance, method overriding, `super()`, polymorphism, and abstract classes.

### Employee Management System

```python
from abc import ABC, abstractmethod
class Employee(ABC):
    def __init__(self, name, base_salary):
        self.name = name
        self.base_salary = base_salary
    @abstractmethod
    def calculate_salary(self):
        pass
    def display_details(self):
        print(f"Name: {self.name}")
        print(f"Salary: {self.calculate_salary()}")

class Developer(Employee):
    def __init__(self, name, base_salary, bonus):
        super().__init__(name, base_salary)
        self.bonus = bonus
    def calculate_salary(self):
        return self.base_salary + self.bonus

class Manager(Employee):
    def __init__(self, name, base_salary, allowance):
        super().__init__(name, base_salary)
        self.allowance = allowance
    def calculate_salary(self):
        return self.base_salary + self.allowance

employees = [
    Developer("Aamir", 70000, 10000),
    Manager("Rahul", 90000, 20000)
]
for employee in employees:
    employee.display_details()
    print("-" * 20)
```

**Output:**

```text
Name: Aamir
Salary: 80000
--------------------
Name: Rahul
Salary: 110000
--------------------
```

### Concepts Used

| Concept | Implementation |
| --- | --- |
| Inheritance | `Developer(Employee)` and `Manager(Employee)` |
| Abstraction | Employee is an abstract base class |
| Method overriding | Both subclasses implement `calculate_salary()` |
| `super()` | Reuses `Employee.init()` |
| Polymorphism | The same `display_details()` call works for each subclass |
| Dynamic dispatch | `display_details()` invokes the subclass’s `calculate_salary()` |

### Internal Execution Flow

**For:**

```python
developer = Developer("Aamir", 70000, 10000)
developer.display_details()
```

**The sequence is:**

- Python creates a Developer object.
- `Developer.__init__()` executes.
- `super().__init__()` initializes the employee’s name and base salary.
- The developer’s bonus is initialized.
- `developer.display_details()` resolves to the inherited method in Employee.
- That method executes `self.calculate_salary()`.
- Because self is a Developer, Python selects `Developer.calculate_salary()`.
- The calculated salary is displayed.

This example illustrates how multiple OOP principles work together.

## 26. Interview Questions and Answers

### Q1. What is inheritance in Python?

Inheritance is an OOP mechanism through which one class derives behavior and attributes from another class, enabling specialization, code reuse, and polymorphism.

### Q2. What are the different types of inheritance in Python?

Single, multilevel, hierarchical, multiple, and hybrid inheritance.

### Q3. Does Python support multiple inheritance?

Yes. A class can inherit from multiple base classes.

```python
class C(A, B):
    pass
```

### Q4. What is method overriding?

It occurs when a subclass defines a method that replaces or specializes an inherited method with the same name.

### Q5. What is `super()`?

`super()` returns a proxy that delegates attribute lookup to the next class in the MRO.

### Q6. What is MRO?

Method Resolution Order defines the order Python uses to search class hierarchies for inherited attributes and methods.

Python uses C3 linearization for ordinary class hierarchies.

### Q7. How do you inspect MRO?

```python
ClassName.mro()
```

**Or:**

```python
ClassName.__mro__
```

### Q8. Does the parent initializer automatically execute when the child overrides `__init__()`?

No. The child initializer must explicitly delegate to the parent or next MRO implementation when needed.

### Q9. What is the diamond problem?

It is a multiple-inheritance situation where different inheritance paths lead to a shared ancestor.

Python uses MRO to resolve method lookup consistently.

### Q10. What is the difference between inheritance and composition?

Inheritance represents specialization or an IS-A relationship. Composition represents an object containing or using another object, commonly described as HAS-A.

### Q11. Can we inherit from built-in Python classes?

Yes.

```python
class MyList(list):
    def first(self):
        return self[0] if self else None

obj = MyList([10, 20, 30])
print(obj.first())
```

**Output:**

```text
10
```

### Q12. Can a child class override a parent class method?

Yes. A child can override instance methods, class methods, static methods, and properties.

### Q13. Can an abstract class be inherited?

Yes. Abstract classes are specifically designed to support inheritance and define contracts for subclasses.

### Q14. Can we prevent inheritance in Python?

Python does not provide a universal built-in final keyword that prevents subclassing at runtime.

**For static type checking, Python supports:**

```python
from typing import final
@final
class SecureClass:
    pass
```

@final communicates that subclasses should not be created, and type checkers can enforce this rule.

However, it does not prevent subclassing at runtime by itself.

For runtime restrictions, classes can implement subclass checks using mechanisms such as `__init_subclass__()`.

### Q15. What happens when two parent classes define the same method?

Python uses MRO to determine which implementation takes precedence.

### Q16. Is inheritance necessary for polymorphism in Python?

No. Duck typing and structural typing can support polymorphism without a shared parent class.

### Q17. Are parent instance attributes copied into the child class?

No. Parent instance attributes are normally initialized on each object by initializers or other methods. Inheritance makes methods and class-level definitions available through attribute lookup; it does not copy the parent’s instance state into the child class definition.

**Output:**


```python
        super().show()
```


The parent implementation executes before each subclass’s remaining statements.

### Question 4: Multiple Inheritance Lookup

```python

        print("B")

    pass
```

```text
A
```

**MRO:**

`C -> A -> B -> object`

### Question 5: Class Attribute Shadowing

```python

    x = 10

    pass

```

```text

10
20
```

The assignment creates an instance attribute rather than changing the class attribute.

### Question 6: Dynamic Dispatch

```python
class A:
    def first(self):
        self.second()
    def second(self):
        print("A")

class B(A):
    def second(self):
        print("B")

B().first()
```

**Output:**

```text
B
```

Although `first()` is defined in A, `self.second()` resolves to `B.second()`.

### Question 7: Explicit Parent Call vs `super()`

```python
class A:
    def show(self):
        print("A")

class B(A):
    def show(self):
        print("B")
        super().show()

class C(A):
    def show(self):
        print("C")
        super().show()

class D(B, C):
    pass

D().show()
```

**Output:**

```text
B
C
A
```

**This is because the MRO is:**

`D -> B -> C -> A -> object`

`super()` in B delegates to C when the object is a D.

## 29. Final Key Takeaways

- Inheritance allows a child class to reuse and specialize functionality defined by a parent class.
- Inheritance generally models an IS-A relationship, while composition generally models HAS-A.
- Python supports single, multilevel, hierarchical, multiple, and hybrid inheritance structures.
- Inherited methods are resolved through the class hierarchy rather than copied into subclasses.
- A child may override an inherited method to customize behavior.
- When a child defines its own `__init__()`, the parent initializer is not automatically executed.
- `super()` delegates to the next applicable implementation in the MRO, not necessarily a fixed parent.
- Python uses C3 linearization to establish a consistent MRO.
- Cooperative multiple inheritance requires compatible methods and correct use of `super()`.
- Inheritance supports runtime polymorphism through overridden methods and dynamic dispatch.
- `isinstance()` and `issubclass()` help inspect relationships between objects and classes.
- Abstract classes define contracts that concrete subclasses must satisfy before instantiation.
- Mixins provide focused reusable behavior through multiple inheritance.
- Python uses naming conventions and name mangling rather than strict traditional access modifiers.
- Class attributes may be shared through inheritance, and mutable class attributes require particular care.
- A well-designed subclass should respect the behavior expected from its base class.
- Prefer composition when inheritance would create an artificial or fragile relationship.

**Core mental model:**

Inheritance establishes a relationship between classes. Python uses that relationship, together with MRO and attribute lookup rules, to determine which attributes and methods are available to an object. Method overriding customizes behavior, while `super()` allows implementations to cooperate along the MRO.

This is the foundation for understanding inheritance from basic syntax through Python’s object model, multiple inheritance, polymorphism, and production-level class design.
