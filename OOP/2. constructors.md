# OOP in Python — Topic 2: Constructors and Their Types

A constructor is associated with object creation and initialization. In Python, when we talk about constructors, we're usually referring to the `__init__()` method.

But there is an important distinction:

- `__new__()` creates the object.
    
- `__init__()` initializes the object after creation.
    

We'll understand both, along with the different constructor patterns commonly discussed in Python interviews.

## 1. Why do we need a constructor?

Consider this example without a custom constructor:

```
class Student:
    pass

s1 = Student()

s1.name = "Aamir"
s1.age = 22
s1.marks = 90
```

This works. But for every new student, we'd have to manually assign the attributes.

A constructor-like initialization method allows us to supply the required data during object creation:

```
class Student:
    def __init__(self, name, age, marks):
        self.name = name
        self.age = age
        self.marks = marks

s1 = Student("Aamir", 22, 90)
```

Now the student is initialized immediately when we create it.

Definition: In everyday Python terminology, `__init__()` is often called the constructor. More precisely, it's an initializer that runs after object creation.

## 2. Types of constructors in Python

Python doesn't formally define separate constructor types like some other languages. However, in tutorials and interviews, constructors are commonly classified as follows:

Constructor patterns in Python

Common educational classification

Default / Implicit

No custom __init__ defined

Non-parameterized

Custom __init__ without extra parameters

Parameterized

__init__ accepts additional values

Copy-style

Initializes using another object's data

These are patterns, not four distinct Python language features.

## 3. Default (implicit) constructor

If you don't write an `__init__()` method, Python can use an initializer inherited from a parent class, usually `object.__init__()`.

```
class Student:
    pass

s1 = Student()

print(s1)
```

This works even though we didn't define an initializer.

The class inherits initialization behavior from `object`.

However, don't assume the implicit initializer automatically creates attributes such as `name` or `age`.

```
class Student:
    pass

s1 = Student()

print(s1.name)
```

Output:

```
AttributeError: 'Student' object has no attribute 'name'
```

Key point: An implicit initializer doesn't automatically create your application's instance attributes.

## 4. Non-parameterized constructor

A non-parameterized constructor is usually taught as an `__init__()` method that takes no additional arguments beyond `self`.

```
class Student:
    def __init__(self):
        self.name = "Unknown"
        self.age = 0

s1 = Student()
s2 = Student()

print(s1.name)
print(s2.age)
```

Output:

```
Unknown
0
```

Notice:

```
def __init__(self):
```

Although the method has `self`, we still call it non-parameterized in this classification because we don't provide any additional initialization values.

### What if we pass an argument?

```
s1 = Student("Aamir")
```

This raises a `TypeError` because our `__init__()` method only expects the instance argument supplied automatically by Python.

### Can objects have different data?

Yes.

```
s1 = Student()
s2 = Student()

s1.name = "Aamir"
s2.name = "Rahul"

print(s1.name)  # Aamir
print(s2.name)  # Rahul
```

Although they start with the same default values, their instance attributes are independent.

## 5. Parameterized constructor

A parameterized constructor accepts additional arguments to initialize objects with different values.

```
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

s1 = Student("Aamir", 22)
s2 = Student("Rahul", 21)

print(s1.name, s1.age)
print(s2.name, s2.age)
```

Output:

```
Aamir 22
Rahul 21
```

Let's examine exactly what's happening.

```
s1 = Student("Aamir", 22)
```

Conceptually, Python invokes:

```
Student.__init__(s1, "Aamir", 22)
```

This is a conceptual representation of the initialization step, after `s1` has been created. Python doesn't literally assign `s1` before making the method call.

Parameter mapping:

|Parameter|Value|
|---|---|
|`self`|Newly created `Student` instance|
|`name`|`"Aamir"`|
|`age`|`22`|

### What if we provide fewer arguments?

```
s1 = Student("Aamir")
```

Output:

```
TypeError: Student.__init__() missing 1 required positional argument: 'age'
```

Python expects all required arguments to be provided.

## 6. Can one constructor behave as both parameterized and non-parameterized?

Yes. This is a particularly useful Python pattern.

We can use default argument values:

```
class Student:
    def __init__(self, name="Unknown", age=0):
        self.name = name
        self.age = age

s1 = Student()
s2 = Student("Aamir")
s3 = Student("Rahul", 21)

print(s1.name, s1.age)
print(s2.name, s2.age)
print(s3.name, s3.age)
```

Output:

```
Unknown 0
Aamir 0
Rahul 21
```

One `__init__()` supports all three calls.

This is common in Python because default arguments and keyword arguments provide flexibility without requiring multiple constructors.

We can also write:

```
s4 = Student(age=25, name="Ali")
```

Here, keyword arguments let us provide values by parameter name.

## 7. Copy constructor — does Python have one?

In languages such as C++, a copy constructor is a specific language-supported feature.

Python doesn't have an equivalent built-in special method named `__copy_constructor__`.

But we can implement copy-style initialization ourselves.

```
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_student(cls, other):
        return cls(other.name, other.age)

s1 = Student("Aamir", 22)

s2 = Student.from_student(s1)

print(s2.name)
print(s2.age)
print(s1 is s2)
```

Output:

```
Aamir
22
False
```

Here, `s2` is a different object initialized using the attributes of `s1`.

Python also supports copying objects with its standard `copy` module:

```
import copy

s3 = copy.copy(s1)
```

Be careful: `copy.copy()` performs a shallow copy, so nested mutable attributes may still be shared. `copy.deepcopy()` recursively copies nested data where possible.

We'll study the differences between shallow and deep copies separately.

## 8. What actually happens when a constructor runs?

This is one of the most important sections for understanding Python internally.

`s1 = Student("Aamir")`

Class is called

Step 1: `__new__()`

Creates and returns a new instance

Step 2: `__init__()`

Initializes the instance's attributes

Step 3: Assignment

The variable `s1` references the resulting object

Let's verify this using code.

```
class Student:
    def __new__(cls, *args, **kwargs):
        print("Inside __new__")
        return super().__new__(cls)

    def __init__(self, name):
        print("Inside __init__")
        self.name = name

s1 = Student("Aamir")
```

Output:

```
Inside __new__
Inside __init__
```

### Important differences

|`__new__()`|`__init__()`|
|---|---|
|Responsible for creating an instance|Responsible for initializing an instance|
|Receives `cls` by convention|Receives `self` by convention|
|Usually returns a new instance|Must return `None`|
|Called before `__init__()`|Called after successful instance creation|
|Often customized for immutable objects|Commonly customized in everyday classes|

If `__new__()` returns something that isn't an instance of the class being called, Python skips that class's `__init__()`.

For most ordinary Python programs, you override `__init__()` and leave `__new__()` alone.

## 9. Can Python have multiple constructors?

This is a very common interview trap.

Consider:

```
class Student:
    def __init__(self):
        print("First constructor")

    def __init__(self, name):
        print("Second constructor")
        self.name = name

s1 = Student("Aamir")
```

Output:

```
Second constructor
```

Why?

Because the second `__init__()` definition replaces the first in the class namespace.

If we write:

```
s2 = Student()
```

We get a `TypeError` for the missing `name` argument.

Python does not support constructor overloading by defining multiple `__init__()` methods with different signatures.

Instead, we normally use default arguments or alternative constructors with `@classmethod`.

### Alternative constructors using `@classmethod`

```
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_birth_year(cls, name, birth_year, current_year):
        age = current_year - birth_year
        return cls(name, age)

s1 = Student("Aamir", 22)

s2 = Student.from_birth_year("Rahul", 2000, 2026)

print(s1.age)
print(s2.age)
```

Output:

```
22
26
```

The class method provides another way to create a `Student`, without declaring another `__init__()`.

The calculated age here is approximate because the birthday may not have occurred yet.

## 10. Constructors and inheritance

What happens when a child class inherits from a parent?

```
class Parent:
    def __init__(self):
        print("Parent initialized")

class Child(Parent):
    pass

c = Child()
```

Output:

```
Parent initialized
```

Since `Child` doesn't define its own `__init__()`, it inherits the parent's initializer.

Now consider:

```
class Parent:
    def __init__(self):
        print("Parent initialized")

class Child(Parent):
    def __init__(self):
        print("Child initialized")

c = Child()
```

Output:

```
Child initialized
```

The parent's initializer does not automatically run here because the child has overridden `__init__()`.

To explicitly invoke the parent initialization, use `super()`:

```
class Parent:
    def __init__(self):
        print("Parent initialized")

class Child(Parent):
    def __init__(self):
        super().__init__()
        print("Child initialized")

c = Child()
```

Output:

```
Parent initialized
Child initialized
```

We'll explore `super()`, the method resolution order (MRO), and multiple inheritance in the inheritance topic.

## 11. Constructor edge cases

### Case A: Can `__init__()` return a value?

```
class Demo:
    def __init__(self):
        return 10

d = Demo()
```

Output:

```
TypeError: __init__() should return None, not 'int'
```

An initializer must return `None`, either implicitly or explicitly.

### Case B: Is `__init__()` called every time you assign an object to a variable?

No.

```
class Demo:
    def __init__(self):
        print("Initialized")

a = Demo()
b = a
c = a
```

Output:

```
Initialized
```

The initializer runs only once here because only one object was created. `b` and `c` reference the existing object.

### Case C: Can we invoke `__init__()` manually?

Yes, although it's rarely desirable.

```
class Student:
    def __init__(self, name):
        self.name = name

s1 = Student("Aamir")

s1.__init__("Rahul")

print(s1.name)
```

Output:

```
Rahul
```

This reinitializes the same object. It doesn't create a new object, and manually reinitializing instances can violate class invariants if not designed for that purpose.

### Case D: Be careful with mutable default arguments

Avoid this:

```
class Student:
    def __init__(self, courses=[]):
        self.courses = courses
```

That default list is created once when the function is defined, so objects that use the default share it.

Prefer:

```
class Student:
    def __init__(self, courses=None):
        self.courses = [] if courses is None else list(courses)
```

This creates a separate list for each instance, including a copy when a list is provided.

## Final recap — What to remember for interviews

|Concept|Key takeaway|
|---|---|
|Default / implicit|Uses inherited initialization if custom `__init__()` is absent|
|Non-parameterized|Only `self`, no extra initialization arguments|
|Parameterized|Takes additional arguments to initialize state|
|Copy-style|Initializes an instance using another object's attributes|
|`__init__()`|Initializes an existing instance|
|`__new__()`|Creates and returns an instance|
|Constructor overloading|Not supported through multiple `__init__()` definitions|
|`@classmethod`|Can provide alternative ways to construct instances|
|`super().__init__()`|Supports cooperative parent initialization|

The key distinction to remember: `__new__()` controls object creation, while `__init__()` controls object initialization. What interviews often call the "types of constructors" are mostly different ways to design `__init__()` and object creation patterns in Python.
