# Topic 2: Constructors

> **TL;DR:** A **constructor** sets up a new object. Python splits this in two: **`__new__()`** creates the instance, **`__init__()`** initializes it. A class has only one `__init__` (no overloading); the "types of constructors" are just patterns for writing it, and `@classmethod` provides alternative constructors.

---

## 1. Why Do We Need a Constructor?

**Problem:** without one, every object's attributes must be set by hand after creation.

```python
class Student:
    pass

s1 = Student()
s1.name = "Aamir"
s1.age = 22
s1.marks = 90
```

- Works, but repetitive and error-prone for every new object.
- **Fix:** supply the data at creation time through `__init__()`.

```python
class Student:
    def __init__(self, name, age, marks):
        self.name = name
        self.age = age
        self.marks = marks

s1 = Student("Aamir", 22, 90)   # initialized immediately
```

- In everyday Python, `__init__()` is called **the constructor**. Precisely, it is an **initializer** that runs *after* `__new__()` creates the object (see Section 8).
- Basics of `__init__` and `self`: [Topic 1: Classes and Objects](1.%20Classes%20and%20Objects.md).

---

## 2. Types of Constructors

Python has **no formal constructor types** (unlike C++/Java). Tutorials and interviews classify common `__init__` patterns:

| Pattern | Meaning |
|---|---|
| **Default / Implicit** | No custom `__init__`; an inherited one is used |
| **Non-parameterized** | Custom `__init__(self)` with no extra parameters |
| **Parameterized** | `__init__` accepts additional values |
| **Copy-style** | Initializes a new object from another object's data |

- These are **patterns**, not four distinct language features.

---

## 3. Default (Implicit) Constructor

If a class defines no `__init__()`, it uses one inherited from a parent class, usually `object.__init__()`.

```python
class Student:
    pass

s1 = Student()
print(s1)   # <__main__.Student object at 0x...>
```

- Works because `Student` inherits initialization behavior from `object`.
- It does **not** create any of your attributes:

```python
class Student:
    pass

s1 = Student()
print(s1.name)
```

```text
AttributeError: 'Student' object has no attribute 'name'
```

- It also accepts **no arguments**: `Student("Aamir")` → `TypeError: Student() takes no arguments`.

---

## 4. Non-Parameterized Constructor

An `__init__()` that takes **no arguments besides `self`**. Every object starts with the same default values.

```python
class Student:
    def __init__(self):
        self.name = "Unknown"
        self.age = 0

s1 = Student()
s2 = Student()

print(s1.name)  # Unknown
print(s2.age)   # 0
```

- Still called "non-parameterized" despite `self`: Python passes `self` automatically; you supply no initialization values.

### Passing an argument fails

```python
s1 = Student("Aamir")
```

```text
TypeError: Student.__init__() takes 1 positional argument but 2 were given
```

- `__init__` only expects the instance that Python supplies automatically.

### Objects can still hold different data

```python
s1 = Student()
s2 = Student()

s1.name = "Aamir"
s2.name = "Rahul"

print(s1.name)  # Aamir
print(s2.name)  # Rahul
```

- Same starting values, but each object's instance attributes are **independent**.

---

## 5. Parameterized Constructor

An `__init__()` that accepts extra arguments, so each object can start with different values.

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

s1 = Student("Aamir", 22)
s2 = Student("Rahul", 21)

print(s1.name, s1.age)  # Aamir 22
print(s2.name, s2.age)  # Rahul 21
```

### What `s1 = Student("Aamir", 22)` does

After the new instance is created, Python conceptually calls:

```python
Student.__init__(new_obj, "Aamir", 22)   # new_obj = the freshly created instance
```

- `s1` is assigned only **after** initialization finishes; Python doesn't bind `s1` first.

| Parameter | Value |
|---|---|
| `self` | Newly created `Student` instance |
| `name` | `"Aamir"` |
| `age` | `22` |

### Fewer arguments than required

```python
s1 = Student("Aamir")
```

```text
TypeError: Student.__init__() missing 1 required positional argument: 'age'
```

- Every required (non-default) argument must be provided.

---

## 6. One Constructor for Both Styles (Default Arguments)

Give parameters **default values** so one `__init__()` works as both non-parameterized and parameterized.

```python
class Student:
    def __init__(self, name="Unknown", age=0):
        self.name = name
        self.age = age

s1 = Student()
s2 = Student("Aamir")
s3 = Student("Rahul", 21)

print(s1.name, s1.age)  # Unknown 0
print(s2.name, s2.age)  # Aamir 0
print(s3.name, s3.age)  # Rahul 21
```

- One `__init__()` supports all three calls.
- **Keyword arguments** pass values by parameter name, in any order:

```python
s4 = Student(age=25, name="Ali")
```

- This is the idiomatic Python replacement for multiple constructors (Section 9).
- Never use a mutable default like `[]` (Section 11, Case D).

---

## 7. Copy Constructor (Copy-Style)

A **copy constructor** builds a new object from an existing one. C++ supports it as a language feature; Python has **no built-in copy constructor** (no special method like `__copy_constructor__`), but you can write one.

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_student(cls, other):
        return cls(other.name, other.age)

s1 = Student("Aamir", 22)
s2 = Student.from_student(s1)

print(s2.name)    # Aamir
print(s2.age)     # 22
print(s1 is s2)   # False
```

- `s2` is a **different object** initialized from `s1`'s attributes.
- Standard alternative: the `copy` module.

```python
import copy

s3 = copy.copy(s1)        # shallow copy
s4 = copy.deepcopy(s1)    # deep copy
```

- `copy.copy()` is **shallow**: nested mutable attributes (lists, dicts) are still **shared**.
- `copy.deepcopy()` recursively copies nested data where possible.
- Details: [Topic 3: Shallow vs Deep Copy](3.%20additional%20topics.md).

## 8. Internals: What Happens When a Constructor Runs

For `s1 = Student("Aamir")`:

1. **The class is called** like a function.
2. **`__new__(cls, ...)`** creates and returns a new instance.
3. **`__init__(self, ...)`** initializes that instance's attributes.
4. **Assignment:** `s1` now references the resulting object.

```python
class Student:
    def __new__(cls, *args, **kwargs):
        print("Inside __new__")
        return super().__new__(cls)

    def __init__(self, name):
        print("Inside __init__")
        self.name = name

s1 = Student("Aamir")
```

```text
Inside __new__
Inside __init__
```

- `super().__new__(cls)` is called **without** the extra args: `object.__new__` raises `TypeError` if you forward them while overriding `__new__`.

### `__new__()` vs `__init__()`

| `__new__()` | `__init__()` |
|---|---|
| **Creates** an instance | **Initializes** an instance |
| Receives `cls` by convention | Receives `self` by convention |
| Usually returns a new instance | Must return `None` |
| Called first | Called after successful creation |
| Customized for immutable types (`int`, `str`, `tuple` subclasses), singletons | Customized in everyday classes |

- If `__new__()` returns something that is **not an instance** of the class being called, Python **skips** that class's `__init__()`.
- In ordinary code, override `__init__()` and leave `__new__()` alone.

## 9. Multiple Constructors? (Overloading)

Python does **not** support constructor overloading. A later `__init__` definition **replaces** the earlier one. (Common interview trap.)

```python
class Student:
    def __init__(self):
        print("First constructor")

    def __init__(self, name):
        print("Second constructor")
        self.name = name

s1 = Student("Aamir")   # Second constructor
s2 = Student()          # TypeError: missing 1 required positional argument: 'name'
```

- The class body runs like ordinary code: the second `def __init__` rebinds the name in the class namespace.
- **Alternatives:** default arguments (Section 6) or alternative constructors with `@classmethod`.

### Alternative Constructors with `@classmethod`

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    @classmethod
    def from_birth_year(cls, name, birth_year, current_year):
        age = current_year - birth_year
        return cls(name, age)

s1 = Student("Aamir", 22)
s2 = Student.from_birth_year("Rahul", 2000, 2026)

print(s1.age)  # 22
print(s2.age)  # 26
```

- Another way to create a `Student` without a second `__init__()`; `cls(...)` still runs the normal `__new__` + `__init__`.
- Using `cls` (not a hardcoded `Student`) means subclasses get instances of the subclass.
- The age is approximate: the birthday may not have occurred yet this year.

## 10. Constructors and Inheritance

### Child without `__init__` inherits the parent's

```python
class Parent:
    def __init__(self):
        print("Parent initialized")

class Child(Parent):
    pass

c = Child()   # Parent initialized
```

### Child overrides `__init__`: parent's does NOT run

```python
class Parent:
    def __init__(self):
        print("Parent initialized")

class Child(Parent):
    def __init__(self):
        print("Child initialized")

c = Child()   # Child initialized
```

### Call the parent explicitly with `super().__init__()`

```python
class Parent:
    def __init__(self):
        print("Parent initialized")

class Child(Parent):
    def __init__(self):
        super().__init__()
        print("Child initialized")

c = Child()
```

```text
Parent initialized
Child initialized
```

- Python never calls the parent initializer implicitly once the child overrides `__init__`.
- `super()`, MRO and multiple inheritance: [Topic 5: Inheritance](5.%20inheritance.md). Constructor chaining: [Topic 3: Additional Topics](3.%20additional%20topics.md).

## 11. Constructor Edge Cases

### Case A: `__init__()` returning a value

```python
class Demo:
    def __init__(self):
        return 10

d = Demo()
```

```text
TypeError: __init__() should return None, not 'int'
```

- An initializer must return `None` (implicitly or explicitly).

### Case B: Assigning an object does not re-run `__init__()`

```python
class Demo:
    def __init__(self):
        print("Initialized")

a = Demo()   # Initialized
b = a        # nothing printed
c = a        # nothing printed
```

- Only one object was created, so `__init__` ran once. `b` and `c` just reference it.

### Case C: Calling `__init__()` manually

```python
class Student:
    def __init__(self, name):
        self.name = name

s1 = Student("Aamir")
s1.__init__("Rahul")

print(s1.name)   # Rahul
```

- Allowed, but rarely desirable. It **reinitializes the same object**; no new object is created.
- Can break class invariants if the class wasn't designed for it.

### Case D: Mutable default arguments

```python
class Student:
    def __init__(self, courses=[]):   # BAD
        self.courses = courses

a = Student()
b = Student()
a.courses.append("Math")
print(b.courses)   # ['Math']  (shared!)
```

- The default list is created **once**, when the function is defined, so every object using the default shares it.

```python
class Student:
    def __init__(self, courses=None):   # GOOD
        self.courses = [] if courses is None else list(courses)
```

- Creates a separate list per instance, and copies a provided list so the caller's list isn't shared either.

## 12. Common Mistakes / Gotchas

- **Defining two `__init__` methods to "overload"** → only the last one exists; calls matching the first signature raise `TypeError`. Use default arguments or `@classmethod`.
- **Overriding `__init__` in a child and forgetting `super().__init__()`** → parent attributes are never set (`AttributeError` later).
- **Mutable default argument (`courses=[]`)** → one list shared by all objects. Use `None` and create the list inside.
- **Returning a value from `__init__`** → `TypeError: __init__() should return None`.
- **Assuming the implicit constructor creates attributes** → `AttributeError` on access.
- **Passing arguments to a class with no/non-parameterized `__init__`** → `TypeError`.
- **Forwarding `*args` to `object.__new__`** in a custom `__new__` → `TypeError`. Call `super().__new__(cls)`.
- **Expecting `copy.copy()` to duplicate nested data** → nested mutables stay shared. Use `copy.deepcopy()`.
- **Hardcoding the class name in an alternative constructor** (`return Student(...)`) → subclasses get the wrong type. Use `cls(...)`.

## 13. Interview Questions

**Q1. Is `__init__()` a constructor?**
Commonly called one, but technically it's an **initializer**. `__new__()` creates the object; `__init__()` sets its state.

**Q2. `__new__()` vs `__init__()`?**
`__new__(cls)` creates and returns the instance and runs first. `__init__(self)` initializes it and must return `None`.

**Q3. Does Python support constructor overloading?**
No. A second `__init__` replaces the first. Use default/keyword arguments or `@classmethod` alternative constructors.

**Q4. Does Python have a copy constructor?**
Not built in. Write one (e.g. a `@classmethod` like `from_student`) or use `copy.copy()` / `copy.deepcopy()`.

**Q5. What happens if a class has no `__init__()`?**
It inherits one (usually `object.__init__`). No attributes are created and the class accepts no arguments.

**Q6. Does the parent's `__init__` run automatically when the child defines its own?**
No. Call it explicitly with `super().__init__()`.

**Q7. Can `__init__()` return a value?**
Only `None`. Anything else raises `TypeError`.

**Q8. Does `b = a` call `__init__` again?**
No. It copies the reference; no new object is created.

**Q9. Can you call `__init__()` manually?**
Yes, it reinitializes the same object. Rarely a good idea.

**Q10. When does Python skip `__init__()`?**
When `__new__()` returns an object that is not an instance of the class being called.

**Q11. When would you override `__new__()`?**
For immutable types (subclassing `int`, `str`, `tuple`) or controlling instance creation (e.g. singletons).

## 14. Practice Questions

**1. What does this print?**

```python
class Demo:
    def __init__(self, x=10):
        self.x = x

a = Demo()
b = Demo(20)
print(a.x, b.x)
```

(a) `10 10`  (b) `10 20`  (c) `20 20`  (d) `TypeError`

<details><summary>Answer</summary>

**(b) `10 20`**: the default `10` is used when no argument is supplied; the second call overrides it with `20`.

</details>

**2. What happens when a class defines two methods named `__init__`?**

(a) Python chooses by argument count  (b) Both run sequentially  (c) The later definition replaces the earlier one  (d) `SyntaxError` occurs

<details><summary>Answer</summary>

**(c)**: class bodies execute like ordinary Python code. Assigning the same method name again replaces the previous binding.

</details>

**3. Which method normally creates the actual instance?**

(a) `__init__`  (b) `__new__`  (c) `__str__`  (d) `__call__`

<details><summary>Answer</summary>

**(b) `__new__`**: it creates the instance; `__init__` initializes it afterwards.

</details>

**4. How many times does `__init__` execute?**

```python
class A:
    def __init__(self):
        print('Hi')

x = A()
y = x
z = A()
```

(a) Once  (b) Twice  (c) Three times  (d) Never

<details><summary>Answer</summary>

**(b) Twice**: `A()` is called twice, creating two objects. `y = x` only copies a reference.

</details>

## Quick Recap

- **Default / implicit** → no custom `__init__`; inherited initialization (usually `object.__init__`), no attributes, no args.
- **Non-parameterized** → `__init__(self)` only; same defaults for every object.
- **Parameterized** → `__init__` takes extra arguments to initialize state.
- **Default arguments** → one `__init__` covers both styles; never use mutable defaults.
- **Copy-style** → initialize from another object's attributes (`@classmethod`), or use `copy.copy()` / `copy.deepcopy()`.
- **`__new__()`** creates and returns the instance; **`__init__()`** initializes it and must return `None`.
- **No overloading**: a second `__init__` replaces the first.
- **`@classmethod`** → alternative ways to construct instances (`cls(...)`).
- **`super().__init__()`** → runs the parent initializer; not automatic once the child overrides `__init__`.
- **`b = a`** never calls `__init__`; only `ClassName()` does.

> **Core idea:** `__new__()` controls object **creation**, `__init__()` controls object **initialization**. The "types of constructors" are just different ways to design `__init__()` and object-creation patterns.
