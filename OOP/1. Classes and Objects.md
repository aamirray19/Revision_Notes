# Topic 1: Classes and Objects

> **TL;DR:** A **class** is a blueprint. An **object** is a concrete instance built from it. Classes bundle **data (attributes)** and **behavior (methods)** together. Every other OOP concept (inheritance, encapsulation, polymorphism, abstraction) builds on this.

---

## 1. Why Classes and Objects?

**Problem:** without OOP, related data and functions are scattered across loose variables.

```python
student1_name = "Aamir"
student1_age = 22
student1_marks = 90

student2_name = "Rahul"
student2_age = 21
student2_marks = 85

def display_student(name, age, marks):
    print(name, age, marks)

display_student(student1_name, student1_age, student1_marks)
display_student(student2_name, student2_age, student2_marks)
```

- Fine for 2 students, unmanageable for 10,000.
- **Fix:** OOP groups a student's **data** (name, age, marks) and **behavior** (study, display) into one unit: an **object**.

---

## 2. Class

A **class** is a blueprint/template for creating objects. Like a house design: it describes the house, but it isn't a house.

```python
class Student:
    pass
```

- `class` → keyword to define a class.
- `Student` → class name (convention: `PascalCase`).
- `pass` → empty placeholder body.
- Defining a class creates **no** objects yet.

---

## 3. Object

An **object** is an **instance** of a class: a concrete thing built from the blueprint.

```python
class Student:
    pass

student1 = Student()
student2 = Student()

print(student1)
print(student2)
```

```text
<__main__.Student object at 0x7f123456>
<__main__.Student object at 0x7f789012>
```

| Piece | Meaning |
|---|---|
| `Student` | The class itself |
| `Student()` | **Calls** the class → creates a new instance |
| `student1` | A variable **referencing** that instance |

- Each `Student()` call creates a new, **independent** object (different addresses; exact values vary per run).

### Class vs Object

| Class | Object |
|---|---|
| Blueprint / template | Instance of the blueprint |
| Defines shared structure and behavior | Holds its own state (data) |
| Defined with `class` | Created with `ClassName()` |
| e.g. `Student` | e.g. `student1` |
| One class → many objects | Each object belongs to a class |

---

## 4. Adding Attributes Dynamically

Python lets you attach attributes to a normal object at any time.

```python
class Student:
    pass

student1 = Student()
student1.name = "Aamir"
student1.age = 22

student2 = Student()
student2.name = "Rahul"
student2.age = 21

print(student1.name)
print(student2.name)
```

```text
Aamir
Rahul
```

- This works because normal objects store attributes in a dictionary (`__dict__`, see Section 9).
- **Problem:** repeating this for every object is tedious and error-prone. **Fix:** `__init__()`.

---

## 5. `__init__()`: The Initializer

`__init__()` is a special method that runs **automatically** right after an object is created, to **set its initial state**.

```python
class Student:
    def __init__(self, name, age, marks):
        self.name = name
        self.age = age
        self.marks = marks

student1 = Student("Aamir", 22, 90)
student2 = Student("Rahul", 21, 85)

print(student1.name)
print(student2.marks)
```

```text
Aamir
85
```

### What happens on `student1 = Student("Aamir", 22, 90)`

1. `__new__()` **creates** (allocates) a new, empty object.
2. `__init__()` is called on that object, with the object passed in as `self`.
3. `"Aamir"`, `22`, `90` are passed to `name`, `age`, `marks`.
4. `__init__` runs `self.name = "Aamir"`, `self.age = 22`, `self.marks = 90`.
5. The finished object is assigned to `student1`.

> **Key point:** `__init__()` **initializes** the object. It does **not create** it; `__new__()` does. More in [Topic 2: Constructors](2.%20constructors.md).

## 6. `self`

`self` is a reference to the **current instance**: the object the method was called on.

```python
class Student:
    def __init__(self, name):
        self.name = name

    def introduce(self):
        print(f"My name is {self.name}")

s1 = Student("Aamir")
s2 = Student("Rahul")

s1.introduce()
s2.introduce()
```

```text
My name is Aamir
My name is Rahul
```

**How it works:** Python passes the object as the first argument automatically.

```python
s1.introduce()   # effectively: Student.introduce(s1)
s2.introduce()   # effectively: Student.introduce(s2)
```

- One method definition serves every object, because `self` changes per call.
- `self` is **not a keyword**, just a convention. This works, but don't do it:

```python
class Student:
    def __init__(this, name):
        this.name = name
```

- Always use `self`. See also [Topic 3: `this` keyword in Python](3.%20additional%20topics.md).

## 7. Attributes and Methods

| Term | Meaning |
|---|---|
| **Attribute** | Data stored on an object (its **state**) |
| **Method** | Function defined in a class that operates on objects (its **behavior**) |

```python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        if amount <= self.balance:
            self.balance -= amount
        else:
            print("Insufficient funds")

    def display_balance(self):
        print(f"Balance: {self.balance}")


account = BankAccount("Aamir", 1000)
account.deposit(500)
account.withdraw(200)
account.display_balance()
```

```text
Balance: 1300
```

- **Instance attributes:** `owner`, `balance`
- **Instance methods:** `deposit`, `withdraw`, `display_balance`
- OOP keeps state and behavior together. (A real version would also reject negative amounts.)

## 8. Instance Attributes vs Class Attributes (interview favorite)

### Instance attributes: one copy per object

```python
class Student:
    def __init__(self, name):
        self.name = name

s1 = Student("Aamir")
s2 = Student("Rahul")

s1.name = "Ali"

print(s1.name)  # Ali
print(s2.name)  # Rahul
```

- Changing `s1.name` does **not** affect `s2`.

### Class attributes: one copy, shared through the class

```python
class Student:
    school = "ABC School"          # class attribute

    def __init__(self, name):
        self.name = name           # instance attribute

s1 = Student("Aamir")
s2 = Student("Rahul")

print(s1.school, s2.school)        # ABC School ABC School

Student.school = "XYZ School"      # change on the CLASS
print(s1.school, s2.school)        # XYZ School XYZ School
```

### Gotcha: assigning through an instance *shadows* the class attribute

```python
s1.school = "Private School"

print(s1.school)       # Private School
print(s2.school)       # XYZ School
print(Student.school)  # XYZ School
```

- `s1.school = ...` creates a **new instance attribute** on `s1` only.
- The class attribute is unchanged; `s1` just stops seeing it.
- **Lookup order:** the instance's `__dict__` first, then the class.

| Instance attribute | Class attribute |
|---|---|
| Defined via `self.attr` (usually in `__init__`) | Defined in the class body |
| Belongs to one object | Shared by all objects through the class |
| Stored in `obj.__dict__` | Stored in `ClassName.__dict__` |
| Update with `obj.attr = ...` | Update with `ClassName.attr = ...` |
| e.g. student name | e.g. school name |

## 9. Internals: How Python Handles Classes and Objects

### Everything is an object

```python
x = 10
name = "Python"
numbers = [1, 2, 3]

print(type(x))        # <class 'int'>
print(type(name))     # <class 'str'>
print(type(numbers))  # <class 'list'>
```

Even classes are objects:

```python
class Student:
    pass

s1 = Student()

print(type(s1))       # <class '__main__.Student'>
print(type(Student))  # <class 'type'>
```

- `s1` is an instance of `Student`.
- `Student` is an instance of `type`. `type` is the default **metaclass** (the "class of classes").

### `__dict__`: where instance attributes live

```python
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

s1 = Student("Aamir", 22)
print(s1.__dict__)    # {'name': 'Aamir', 'age': 22}

s1.city = "Mumbai"
print(s1.__dict__)    # {'name': 'Aamir', 'age': 22, 'city': 'Mumbai'}
```

- This dictionary is why you can add attributes dynamically.
- Not every object has one: classes using `__slots__` restrict their attributes and have no instance `__dict__`.

### Identity vs equality: `is` vs `==`

```python
class Student:
    def __init__(self, name):
        self.name = name

s1 = Student("Aamir")
s2 = Student("Aamir")

print(s1 is s2)   # False
print(s1 == s2)   # False
```

| Operator | Checks | Default for custom classes |
|---|---|---|
| `is` | Same object in memory (**identity**) | Always identity |
| `==` | Equal value (calls `__eq__`) | Falls back to identity, so it behaves like `is` |

- Same data ≠ same object.
- Override `__eq__()` to compare objects by value.

## 10. References: Multiple Variables, One Object

```python
class Student:
    def __init__(self, name):
        self.name = name

s1 = Student("Aamir")
s2 = s1            # copies the REFERENCE, not the object

s2.name = "Rahul"

print(s1.name)     # Rahul
print(s2.name)     # Rahul
print(s1 is s2)    # True
```

- `s2 = s1` creates **no new object**. Both names point to the **same** object.
- A change made through either name is visible through both.
- For an independent copy, use `copy.copy()` / `copy.deepcopy()`. See [Topic 3: Shallow vs Deep Copy](3.%20additional%20topics.md).

## 11. Common Mistakes / Gotchas

- **Forgetting `self` in a method definition** → `TypeError: ... takes 0 positional arguments but 1 was given`.
- **Writing `name = name` instead of `self.name = name`** in `__init__` → the value is never stored on the object.
- **Updating a class attribute through an instance** (`obj.attr = x`) → it shadows instead of updating. Use `ClassName.attr = x`.
- **Returning a value from `__init__`** → `TypeError: __init__() should return None`.
- **Assuming `b = a` copies an object** → it only copies the reference.
- **Expecting `==` to compare data** on custom classes → it compares identity until you define `__eq__`.

## 12. Interview Questions

**Q1. Can a class exist without objects?**
Yes. Defining a class doesn't require creating any instances.

**Q2. Can we create an object without defining a custom class?**
Yes. `x = 10` creates an instance of the built-in `int` class.

**Q3. Is `__init__()` mandatory?**
No. A class can be instantiated without an explicit `__init__()`.

**Q4. Can one class create multiple objects?**
Yes. Each call normally creates a new instance (a class *can* customize this, e.g. singletons).

**Q5. `Student` vs `Student()`?**
`Student` is the class object; `Student()` calls it to create an instance.

**Q6. What if `__init__()` returns a value?**
Returning anything other than `None` raises a `TypeError`.

**Q7. `__new__()` vs `__init__()`?**
`__new__()` creates and returns the object; `__init__()` then sets up its attributes. See [Topic 2](2.%20constructors.md).

## 13. Practice Questions

**1. What does this print?**

```python
class A:
    x = 10

a = A()
b = A()
a.x = 20

print(a.x, b.x, A.x)
```

(a) `20 20 20`  (b) `20 10 10`  (c) `10 10 10`  (d) `20 20 10`

<details><summary>Answer</summary>

**(b) `20 10 10`**: `a.x = 20` creates an instance attribute on `a` that shadows `A.x`. `b` and `A` still see the class attribute.

</details>

**2. What is the role of `self` in an instance method?**

(a) A reserved keyword  (b) A reference to the current instance  (c) A reference to the parent class  (d) A way to create a new object

<details><summary>Answer</summary>

**(b)**: Python automatically passes the instance the method was called on as the first argument. By convention it's named `self`.

</details>

**3. What does this print?**

```python
class Demo:
    def __init__(self, value):
        self.value = value

a = Demo(5)
b = a
b.value = 99

print(a.value, a is b)
```

(a) `5 False`  (b) `5 True`  (c) `99 False`  (d) `99 True`

<details><summary>Answer</summary>

**(d) `99 True`**: `b = a` copies the reference, not the object. Both names point to the same instance.

</details>

## Quick Recap

- **Class** → blueprint defining attributes + behavior.
- **Object** → an instance of a class; holds its own state.
- **`__new__()`** creates the object; **`__init__()`** initializes it (must return `None`).
- **`self`** → the instance the method was called on; a convention, not a keyword.
- **Instance attributes** → per object, stored in `obj.__dict__`.
- **Class attributes** → shared, stored on the class; assigning through an instance **shadows** them.
- **Everything is an object**, even classes (they're instances of `type`).
- **`is`** = identity, **`==`** = equality (defaults to identity for custom classes).
- **`b = a`** copies the reference, not the object.

> **Core idea:** classes define behavior, objects hold state, and Python connects them through references and attribute lookup.
