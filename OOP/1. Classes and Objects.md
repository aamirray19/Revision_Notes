# OOP in Python — Topic 1: Classes and Objects

Classes and objects are the foundation of Object-Oriented Programming (OOP). Almost every other OOP concept—inheritance, encapsulation, polymorphism, and abstraction—builds on them.

We'll understand them from the basics, explore how Python handles them internally, and then cover interview-level concepts.

## 1. Why do we need classes and objects?

Imagine you're developing a student management system.

Each student has certain data:

- Name
    
- Age
    
- Roll number
    
- Marks
    

And each student can perform certain actions:

- Study
    
- Attend classes
    
- Display their details
    

Without OOP, you might write:

```
student1_name = "Aamir"
student1_age = 22
student1_marks = 90

student2_name = "Rahul"
student2_age = 21
student2_marks = 85

def display_student(name, age, marks):
    print(name, age, marks)

display_student(student1_name, student1_age, student1_marks)
display_student(student2_name, student2_age, student2_marks)
```

This works, but imagine managing 10,000 students. Keeping their data and related functions organized becomes difficult.

OOP solves this by grouping related data and behavior into objects.

## 2. What is a class?

A class is a blueprint or template used to create objects.

Think of a class as the design of a house. The design describes what the house will contain, but it isn't an actual house.

One class can create multiple independent objects.

### Basic Python class syntax

```
class Student:
    pass
```

Here:

- `class` is the Python keyword for defining a class.
    
- `Student` is the class name.
    
- `pass` is a placeholder that does nothing.
    

We have defined a class, but haven't explicitly created any students yet.

## 3. What is an object?

An object is an instance of a class.

The class describes a structure and behavior; an object is a concrete instance created from that class.

```
class Student:
    pass

student1 = Student()
student2 = Student()

print(student1)
print(student2)
```

Example output:

```
<__main__.Student object at 0x7f123456>
<__main__.Student object at 0x7f789012>
```

The hexadecimal numbers are representation details and will vary.

Let's understand:

```
student1 = Student()
```

- `Student` refers to the class.
    
- `Student()` invokes the class to create an instance.
    
- `student1` is a variable referring to the resulting object.
    

Calling `Student()` a second time ordinarily creates another independent object.

### Class vs Object

|Class|Object|
|---|---|
|Blueprint or template|Instance of the blueprint|
|Defines shared behavior and structure|Holds particular state|
|Defined using `class`|Commonly created using `ClassName()`|
|Example: `Student`|Example: `student1`|
|Can create many instances|Is an instance of a class|

## 4. How do we store data inside objects?

Let's improve our example:

```
class Student:
    pass

student1 = Student()
student1.name = "Aamir"
student1.age = 22

student2 = Student()
student2.name = "Rahul"
student2.age = 21

print(student1.name)
print(student2.name)
```

Output:

```
Aamir
Rahul
```

Notice that we added attributes dynamically:

```
student1.name = "Aamir"
```

Python allows this for normal user-defined class instances because they typically have an instance attribute dictionary.

But manually assigning attributes to every student becomes repetitive.

That's where `__init__()` comes in.

## 5. The `__init__()` method

`__init__()` is a special method that initializes an object.

```
class Student:
    def __init__(self, name, age, marks):
        self.name = name
        self.age = age
        self.marks = marks

student1 = Student("Aamir", 22, 90)
student2 = Student("Rahul", 21, 85)

print(student1.name)
print(student2.marks)
```

Output:

```
Aamir
85
```

Let's break this down carefully.

### What happens during object creation?

When Python executes:

```
student1 = Student("Aamir", 22, 90)
```

For this normal class, Python:

1. Calls the class to create an object (through `__new__()`).
    
2. Invokes `__init__()` on the new object.
    
3. Passes the new object as `self`.
    
4. Passes `"Aamir"`, `22`, and `90` to the remaining parameters.
    
5. Assigns the resulting object to `student1`.
    

The initializations are effectively:

```
self.name = "Aamir"
self.age = 22
self.marks = 90
```

Importantly, `__init__()` initializes the object; it does not actually create it. Object allocation is generally handled by `__new__()`.

## 6. What exactly is `self`?

This is one of the most important Python OOP concepts.

`self` refers to the particular instance on which an instance method is being called.

Consider:

```
class Student:
    def __init__(self, name):
        self.name = name

    def introduce(self):
        print(f"My name is {self.name}")

s1 = Student("Aamir")
s2 = Student("Rahul")

s1.introduce()
s2.introduce()
```

Output:

```
My name is Aamir
My name is Rahul
```

When we write:

```
s1.introduce()
```

It is effectively equivalent to:

```
Student.introduce(s1)
```

And:

```
s2.introduce()
```

Is effectively:

```
Student.introduce(s2)
```

So the same method can operate on different objects.

### Is `self` a Python keyword?

No. `self` is a naming convention, not a reserved keyword.

This technically works:

```
class Student:
    def __init__(this, name):
        this.name = name
```

But always prefer `self`, because that's the standard Python convention.

## 7. Attributes and methods

An object commonly contains two important things:

Attributes: Data associated with an object.

Methods: Functions associated with a class that can operate on objects.

Example:

```
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        if amount <= self.balance:
            self.balance -= amount
        else:
            print("Insufficient funds")

    def display_balance(self):
        print(f"Balance: {self.balance}")


account = BankAccount("Aamir", 1000)

account.deposit(500)
account.withdraw(200)
account.display_balance()
```

Output:

```
Balance: 1300
```

Here, `owner` and `balance` are instance attributes, while `deposit`, `withdraw`, and `display_balance` are instance methods.

This illustrates how OOP brings state and behavior together. A production bank account would also validate amounts to prevent negative deposits and withdrawals.

## 8. Instance attributes vs class attributes

This distinction is frequently asked in interviews.

### Instance attributes

These belong to individual objects.

```
class Student:
    def __init__(self, name):
        self.name = name

s1 = Student("Aamir")
s2 = Student("Rahul")

s1.name = "Ali"

print(s1.name)  # Ali
print(s2.name)  # Rahul
```

Changing the instance attribute of `s1` does not change `s2`.

### Class attributes

These are attributes stored on the class and ordinarily shared through class-level lookup.

```
class Student:
    school = "ABC School"

    def __init__(self, name):
        self.name = name

s1 = Student("Aamir")
s2 = Student("Rahul")

print(s1.school)
print(s2.school)
```

Output:

```
ABC School
ABC School
```

Now change the class attribute:

```
Student.school = "XYZ School"

print(s1.school)
print(s2.school)
```

Output:

```
XYZ School
XYZ School
```

But here's a subtle point:

```
s1.school = "Private School"

print(s1.school)       # Private School
print(s2.school)       # XYZ School
print(Student.school)  # XYZ School
```

The assignment `s1.school = ...` created an instance attribute that shadows the class attribute for `s1`. It did not change the class attribute.

|Instance attribute|Class attribute|
|---|---|
|Usually defined using `self.attribute`|Usually defined in the class body|
|Specific to an instance|Looked up through the class|
|Typically stored in the object's `__dict__`|Stored in the class's `__dict__`|
|Example: student name|Example: school name|

## 9. Classes and objects internally in Python

Here's where the deeper understanding starts.

### Everything is an object in Python

```
x = 10

print(type(x))
```

Output:

```
<class 'int'>
```

Even the integer `10` is an instance of the `int` class.

Similarly:

```
name = "Python"
numbers = [1, 2, 3]

print(type(name))     # <class 'str'>
print(type(numbers))  # <class 'list'>
```

What about the `Student` class itself?

```
class Student:
    pass

print(type(Student))
```

Output:

```
<class 'type'>
```

By default, classes you define are themselves objects created by the metaclass `type`.

This leads to an important distinction:

```
class Student:
    pass

s1 = Student()

print(type(s1))       # <class '__main__.Student'>
print(type(Student))  # <class 'type'>
```

In short:

- `s1` is an instance of `Student`.
    
- `Student` is itself an instance of `type`.
    

### Understanding `__dict__`

Most regular Python objects have a `__dict__` that stores their instance attributes.

```
class Student:
    def __init__(self, name, age):
        self.name = name
        self.age = age

s1 = Student("Aamir", 22)

print(s1.__dict__)
```

Output:

```
{'name': 'Aamir', 'age': 22}
```

Now:

```
s1.city = "Mumbai"

print(s1.__dict__)
```

Output:

```
{'name': 'Aamir', 'age': 22, 'city': 'Mumbai'}
```

This explains why normal Python objects can dynamically acquire attributes.

Not all objects have an instance `__dict__`, however. Classes using `__slots__`, for example, can restrict instance attributes.

### Object identity

Two objects may contain identical data but still be different objects.

```
class Student:
    def __init__(self, name):
        self.name = name

s1 = Student("Aamir")
s2 = Student("Aamir")

print(s1 is s2)
print(s1 == s2)
```

Output:

```
False
False
```

Why?

- `is` checks object identity.
    
- `==` checks equality using the class's equality behavior.
    

By default, ordinary user-defined objects inherit identity-based equality. We can customize `==` using `__eq__()`, a topic we'll cover with special methods.

## 10. Multiple variables referencing the same object

This is an essential interview scenario:

```
class Student:
    def __init__(self, name):
        self.name = name

s1 = Student("Aamir")
s2 = s1

s2.name = "Rahul"

print(s1.name)
print(s2.name)
print(s1 is s2)
```

Output:

```
Rahul
Rahul
True
```

Why?

Because `s1` and `s2` reference the same object. The assignment `s2 = s1` does not create a new `Student`.

Both variables point to one shared object, not two separate objects.

This is why understanding references, identity, and mutability is so important in Python.

## 11. Common interview questions

Q1. Can a class exist without objects?

Yes. Defining a class does not require creating any instances of it.

Q2. Can we create an object without defining a custom class?

Yes. For example, `x = 10` gives you an integer object, which is an instance of the built-in `int` class.

Q3. Is `__init__()` mandatory?

No. A class can exist and be instantiated without defining an explicit `__init__()`.

Q4. Can one class create multiple objects?

Yes. Each call normally produces a new instance, although a class can customize creation behavior.

Q5. What's the difference between `Student` and `Student()`?

`Student` refers to the class object, while `Student()` calls the class to produce an instance.

Q6. What happens if `__init__()` explicitly returns a value?

Returning a non-`None` value causes a `TypeError`. Python requires `__init__()` to return `None`.

## Final recap

- Class: A blueprint defining attributes and behavior.
    
- Object: An instance of a class.
    
- `__init__()`: Initializes a newly created instance.
    
- `self`: Refers to the instance receiving a method call.
    
- Instance attributes: Hold per-object state.
    
- Class attributes: Belong to the class and can be accessed through instances.
    
- `is` vs `==`: Identity versus equality.
    
- References: Multiple variables can point to the same object.
    

The most important takeaway is that classes define behavior, objects hold state, and Python manages their relationship through references and attribute lookup.
